# Review - confirmed defects and their fix status

The playtest work list: the defects the owner confirmed by playing the build, each with its
reproduction and its fix status. Split out of [`PLAN.md`](PLAN.md) on 2026-11-22 so the plan stays a
phase checklist - `PLAN.md` remains the source of truth for progress, this file for what is still
wrong.

**Live scene gallery:** [`review/scenes.html`](review/scenes.html) shows every implemented screen
captured from the running build, with the live values each one is showing. Regenerate it with
`tools/godot/scene_gallery.gd` + `tools/review/build_scenes.py` whenever a fix changes what a screen
looks like, so the rows below can be checked against the current build rather than a stale capture.

## Rules

- A row starts `OPEN` and only becomes `FIXED` once the behaviour is verified against the original,
  covered by a headless check where it can be, and re-shotted windowed for anything visual. Status
  words: `RE-CHECK` (an existing fix may already cover it), `FIXED` (dated, with its `EV-`/`D-` refs)
  and `COVERED` (another row's fix answers it).
- Rows are append-only in the spirit of `EVIDENCE.md`: a fixed row keeps its text and gains a dated
  status, and a later pass that changes a finding adds a dated note instead of rewriting the row.
- New defects append as the next `R` number; numbers are never reused or renumbered.
- Final-touch feedback is triaged from [`polish.md`](polish.md): its 15 owner items are R52-R66 (R54
  confirmed covered by R51 on a windowed re-check, EV-0233; R66 fixed 2026-11-22, EV-0234; the rest
  open). The agent suggestions in
  that file stay untracked here.
