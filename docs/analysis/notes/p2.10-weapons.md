## 1. There is no laser object: a click *is* the shot

`FUN_00543920(x, y, button)` is the tank mouse handler bound to the playfield
(`FUN_0046E3A0(x, y, button)` runs first as the base handler). It resolves one click against
this chain, stopping at the first hit that returns non-zero (EV-0122):

| # | target | call | note |
| --- | --- | --- | --- |
| 0 | bonus round | `FUN_00537F40` / `FUN_0053BFB0` | only when `Tank+0x2A5 != 0` (P2.6) |
| 1 | `Tank+0xBC` list | `Alien::HitTest` `FUN_004FA6F0` | **only while `Tank+0x110` (boss) is set** and `y > 40` |
| 2 | `Tank+0x110` (boss) | `Alien::HitTest` `FUN_004FA6F0` | one extra call, `y > 40` |
| 3 | `Tank+0xB8` (aliens) | `Alien::HitTest` `FUN_004FA6F0` | skipped when the list is empty or the first alien is a Gus (`kind 4`) with no boss alive |
| 4 | `Tank+0xDC` list | `Larva::HitTest` `FUN_004D82A0` | explodes kind 0, deflects kind 1 |
| 5 | `Tank+0xF4` list | `Missle::HitTest` `FUN_004FFAE0` | shoots projectiles down |
| 6 | feed the fish | `SpendMoney(Tank+0x4AC, 1)` + `FUN_00543280(x-10, y-10, 0, 0, variant, -1)` | inside `x 31..586`, `y 61..399`, no aliens/projectiles |

- A resolved click draws the laser spark with `FUN_00543640(x - 0x28, y - 0x28)` and the
  handler ends with `FUN_00538AE0()`. The alien/projectile branches also stamp `Tank+0x4ED = 1`
  and `Tank+0x3C4 = FUN_00537B60()` (tick stamp); the feeding path sets `Tank+0x4EC = 1` and
  `Tank+0x3C0 = FUN_00537B60()` instead.
- The `y > 40` guard on the alien branches is the water line: clicks above it (HUD band) are not
  shots. The feed branch is the only one with a *full* rectangle test (`x 31..586`,
  `y 61..399`).
- Clicking a Gus (kind 4) with no boss alive skips the alien loop and instead tests
  `FUN_004D46F0(x, y)`; on a hit it drops food with variant `0x14` (star potion pellet) through
  the same `FUN_00543280` (P2.3 §4 keeps the pellet semantics).
- **Consequence**: the remake needs one input handler that raycasts/box-tests in this order.
  There is no beam entity, no projectile owned by the player and no "weapon cooldown" object -
  the only rate limit is the per-alien `+0x200` cooldown described in P2.9 §6.

## 2. Damage per shot and the rate limit

Damage lives entirely in `Alien::HitTest` (P2.9 §6, EV-0120):

```c
if (Alien+0x200 > 0) return 0;                 /* 10-tick per-alien cooldown */
hp -= (kind == 5 || kind == 6) ? Tank+0x3E4 * 2 + 2 : Tank+0x3E4 * 3;
...
Alien+0x200 = 10;
```

So the "laser" is a pure function of the weapon level, and the same click can hit **one**
alien in the `Tank+0xB8` loop (the loop breaks on the first hit) but can still fall through to
the projectile lists when every alien misses.

## 3. Weapon level (`Tank+0x3E4`) - 2 to 12, rapid fire at 12

`Tank::BuyItem` case 10 (`FUN_00549380`, EV-0123):

```c
case 10:
  if (Tank+0x3E4 < 0xc && Tank::SpendMoney(price, quiet)) {
      Tank+0x3E4 += 1;
      FUN_005406A0(10, /*hint*/ ...);          /* store refresh */
  }
```

- The cap is **12** (`< 0xc`), not `0xB`. This corrects EV-0057's "weapon `Tank+0x3E4` max 0xB".
- Levels by context: **2** at level start (EV-0063), **8** in demo (EV-0063), **10** forced when
  the boss spawns (EV-0113), 1..12 reachable through store item 10.
- Damage therefore ranges **6 (level 2) .. 36 (level 12)**; the boss fight sits at 30. EV-0121
  cross-checks level 2 against the wiki's hit counts (50/6 = 9 hits for a Sylvester, etc.).
- `FUN_005406A0(item, show_hint)` is the post-purchase store refresh. Its weapon branch calls
  `FUN_00530410()` and, when `Tank+0x3E4 > 0xB` (i.e. the 11 -> 12 purchase) **and** the hint
  flag is set, shows `"Hold down mouse button for Rapid Fire!"` (0x5A82C8) via
  `FUN_0041D8B0` before `FUN_00534450()`. So level 12 is not just +3 damage: it unlocks
  **hold-to-fire**. (The sibling hint `"Hold down mouse button to Auto-Feed!"` is 0x5A8AB4,
  shown by the food-quantity purchase.)
- Rapid fire is implemented in the **tank update** (`FUN_00547610`, EV-0129). The click arms
  `Tank+0x4ED = 1` and stamps `Tank+0x3C4`; the update then, while the mouse button latch
  `FUN_0046CCE0()` (= `Tank+0xEC & 1`) is held, checks `Tank+0x3E4 > 0xB`,
  `tick % (0xB - Tank+0x3E4 / 2) == 0`, `now() > Tank+0x3C4 + 100` and `click_y > 0x28`, and
  re-runs **only** the missile/larva/alien hit tests plus the spark. It repeats nothing else
  (no boss, no `Tank+0xBC` list, no feed), so rapid fire is a narrower path than the first click.

## 5. Alien projectiles: one class pair, three kinds

`Sexy::Missle` derives from `Sexy::Larva` (`p2.2-module-rtti-classes.txt`: vtable `0x5DF5F0`
vs base `0x5DF5D4`); both share the generic object base. Slot 22 (the update virtual) is
`0x4FFB30` for `Missle` and `0x4F2930` for `Larva`.

### 5.1 Spawner `FUN_00544130(x, y, target, kind)`

```c
obj = new 0x1B8;  FUN_004EAE40(x, y, target, kind);     /* ctor */
FUN_00542EE0(obj, 0);                                   /* register */
[this+0x10]->vtable[+0xC](obj);                         /* add to the render/scene list */
[this+0x10]->vtable[+0x2C](obj);
[this+0x10]->vtable[+0x2C]([this+0x100]);                /* z-order, twice */
if (FUN_004D80C0() == 0) target->[0x98] = obj;           /* the victim remembers its projectile */
```

The guard was read as "not demo" in EV-0124; on a projectile `+0x19C` is the kind, so
`FUN_004D80C0()` is false and the lock is **always** set in retail play (EV-0130).
Destructor calls the spawner with `kind = 0`, Ulysses with `kind = 1` (P2.8 §8.1/§8.2, EV-0124).

### 5.2 Ctor `FUN_004EAE40(x, y, target, kind)`

| field | value |
| --- | --- |
| `+0x158` / `+0x160` (double) | x / y (the object's float position; `+0x30`/`+0x34` ints are the ftol copies) |
| `+0x19C` | `kind` (0 missile, 1 energy ball, 2 third variant) |
| `+0x1A4` | `target` pointer (homing victim) |
| `+0x168` / `+0x170` (double) | vx / vy: 0 at spawn (the random branch below is dead) |
| `+0x38` / `+0x3C` | box 80x80, or **50x50** when `kind == 2` |
| `+0x188` (double) | speed divisor 0.8, or **0.4** when `kind == 2` |
| `+0x194` / `+0x198` | 1 / 1 |
| `+0x1A8` / `+0x1AC` | 0 / 10 (the "hit, now expire in 10 ticks" counter) |
| `+0x17C` | 15 (spawn immunity / life tick) |
| `+0x1A0` | `rand() & 3` (phase) |
| `+0x190` | 0 (byte flag, see 5.4) |
| `+0x8C` | 0x1E (30, generic timer) |

The ctor ends with `if (FUN_004D80C0() != 0) { vx = {-6,-5,-4,+4,+5,+6}[rand()%6]; vy = same; }`.
Because the guard tests the object's own kind (`+0x19C` = 0/1/2) it can never pass, so in retail
play the projectile **always starts still** and is steered by `FUN_004FF4E0` (homing, EV-0158).
Keep the random branch out of the remake (EV-0130).

### 5.3 `Missle::Update` (`FUN_004FFB30`)

- Early-out when `Tank == 0` or `Tank+0x94 != 0` (tank paused/overlay).
- Expiry: if `+0x1A8 > 0` it counts up and at `>= +0x1AC (10)` calls `FUN_004D80E0()` (remove).
- Homing step `FUN_004FF4E0()` runs before the bounds test and can end the object.
- Bounds by kind: kind 0 is **clamped** into the tank (`x 10..550`, `y 95..370`); kinds 1 and 2
  **die** outside a wider rect (`x -20..580`, `y 45..380`), kind 1 only after `+0x190` is set.
- kind 2 gets gravity: `vy += 0.2` per tick while `+0x190` is set.
- Movement is `x += vx / speed`, `y += vy / speed` (the same divisor convention as aliens).
- `+0x17C` counts down (spawn immunity).
- kind 0 and `rand() % 3 == 0`: spawns an 8-px smoke particle at the missile tail
  (`FUN_005436F0`), i.e. the missile leaves a trail.

### 5.4 Hit tests (clicking a projectile)

- `Missle::HitTest` `FUN_004FFAE0(x, y)`: if `+0x158 != 0`, run `FUN_004FE480(x, y)`; on a hit
  spawn a 2-px burst at `(x-40, y-40)` and return 1. So a missile can be shot down.
- `Larva::HitTest` `FUN_004D82A0(x, y)`:
  - `kind 1`: box = `(+0x158+10 .. +0x158+70)` x `(+0x160+10 .. +0x160+70)`, only while
    `+0x17C < 1`; the object is **deflected**: `vx = ((click.x - x0) - 40) / -5`,
    `vy = ((click.y - y0) - 40) / -5`, each clamped to `[+1, -1]`, then `+0x190 = 1` and a
    2-px burst.
  - `kind 0`: 60x60 box centred on the object; `+0x17C < 1` -> `FUN_004D80E0()` (destroy) plus
    the burst.
  - `kind 2`: no case - a Larva cannot be clicked.

### 5.5 `Larva::Update` (`FUN_004F2930`) - the non-projectile use of the same class

Same pause gate and base update as the missile, then two modes keyed by the byte at `+0x5D`:

- mode 0: falls (`y -= vy`); reaching `y < 64` despawns through `FUN_004D9570()`; `x > 530`
  wraps to 530.
- mode 1: lerps towards `(550, 30)` by 1/7 of the distance per tick; when the integer y drops
  below 40 it despawns, increments `Tank+0x4A8` and calls `FUN_0053C1E0(...)` (the Shells
  routing helper of P2.6) - i.e. **this object pays out shells when it reaches the corner**.

Which game object that is (a "larva" that falls, hatches or pays shells) is not established by
the code we have; the class is reused by the missiles, so do not model it as a missile variant
(Q-0023).

### 5.6 Homing and the on-target check (EV-0158)

`FUN_004FF4E0` (recovered 2026-11-07) is the steering body `Missle::Update` calls before its
bounds test. Order: target-loss expiry, deflected shots skip steering, `x` then `y` steering,
then `FUN_004FC070`. The sample is `position + offset` (40 for kinds 0/1, 25/40 for kind 2)
against the victim's integer position (`+0x30`/`+0x34`). Steps are `+-0.2` toward caps of
`1.8` (Ultravore wide bands: `+200` far / `+110` mid / inner `1.4`/`0.6` with a `0.1`-step
`+-0.2` vertical deadband; everyone else tight bands: `+80`/`+60`, same near caps and fine
deadband). The on-target check tests the `+40` sample against the locked victim's box
(`10..70`; Ultravore `8..140` x `4..140`), kills via slot 77 and consumes the shot; a kind-2
hit bounces (divisor `1.5`, velocity flipped, shot survives); a deflected ball scans aliens/
boss (30 damage, consumes) and fish (die, survives). No eligible fish means no shot
(`FUN_004E8DF0`, farthest wins).

## 6. Implementation spec for P4

1. **One click handler, six stages** in the order of §1 (bonus → boss lists → aliens →
   `+0xDC` → `+0xF4` → feed). Stop at the first success; draw the spark on any hit.
2. **Shots have no cooldown of their own** - only the per-alien 10-tick cooldown from
   `Alien+0x200`. Cap the click rate at frame rate; do not add a weapon cooldown.
3. **Damage** `= 3 * weapon_level` (`2*speed+2` for Destructor/Ulysses), weapon level in
   `2..12`, `10` during the boss fight.
4. **Weapon level 12 unlocks hold-to-fire** ("Rapid Fire"), exact rule in §3: period
   `11 - weapon_level / 2` ticks (5 at level 12), at least 100 ms between repeats, only while
   the mouse button is held, and it re-tests missiles -> larvae -> aliens only.
5. **Feed rectangle** `x 31..586`, `y 61..399`; the shot branches only need `y > 40`.
6. **Projectiles**: one class with `kind` 0 (Destructor missile, 80x80, speed 0.8, homing,
   clamped to `x 10..550 / y 95..370`, smoke trail), kind 1 (Ulysses ball, dies outside
   `x -20..580 / y 45..380`, deflectable) and kind 2 (50x50, speed 0.4, gravity 0.2).
   Expiry after 10 ticks once `+0x1A8` starts, 15-tick spawn immunity.
7. **Clicking a projectile** destroys a missile/kind-0 larva and deflects a kind-1 larva
   (velocity away from the click, clamped to +-1, flag `+0x190`).
8. **Victim pointer** `target+0x98` is how the fish knows a projectile is locked on; the spawner
   always sets it (EV-0130). Clear it when either side dies (P2.8 §9 already detaches `+0x98`).
9. **Homing** (§5.6, EV-0158): `+-0.2` steps toward `1.8` with Ultravore wide vs tight bands,
   target-loss expiry for kinds 0/1, single-victim kill via the `10..70` box (Ultravore
   `8..140` x `4..140`), deflected-ball 30 damage vs aliens/boss and pass-through fish kills.
   The `Tank+0xF4`/`+0xB4`/`+0xB0` scan lists and the type-0 picker gate stay unmodelled.
10. **Unknowns to keep parameterised**: laser draw/frame selection (`IMAGE_LASERS`,
   `IMAGE_LASERUPGRADES`), the `Tank+0xBC` list identity and `Larva`'s gameplay role.
