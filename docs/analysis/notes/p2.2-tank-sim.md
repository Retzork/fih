## 5. `Fish::Update` (0x4F6970) - anatomy

4,440 bytes, 0 in-module callers (dispatched only via vtable). `this` = Fish*.

### 5.1 Gates (early return)

- `this[0x22]` (+0x88) = tank/screen pointer; `tank+0x730` = tank fish/entity manager pointer;
  if manager == 0 → return.
- `manager+0x94` (char) = paused flag; if set → return.
- First call: `FUN_004f22c0()` (common per-tick helper, not yet decompiled).
- Virtual gate: slot 82 (`*this + 0x148`) returns bool = **true → skip all AI** (identity TBD;
  candidate: "being eaten/held/dead-in-progress").

### 5.3 Swim mode machine

`mode = this[0x6b]` (+0x1AC). Every tick after the machine: `[0x6c]++`, `[0x6d]++`; when
`[0x6d] > 20` → reset to 0 and **10 % chance** to pick `mode = rand()%9 + 1` (average ~2 s
between random changes). Constants are px / per-tick (divide by `this[0x60]` speed divisor
during integration).

| Mode | Preset/behavior |
| --- | --- |
| 0 | once (if dart counter 0): vy = +0.5; glide `y -= 0.25/div` every tick; every 40 frames pull vx toward 0 (∓0.5 step when \|vx\|>0.5) and re-roll `[0x6f]` |
| 1 | once: vy = -8.0 (up-dash); every 40 frames vx → +1 (±1 steps, saturating); glide `y -= 0.5/div` |
| 2 | once: vy = -8.0; every 40 frames vx → -1; glide `y -= 0.5/div` |
| 3 | every 40 frames: vx → -1; vy → +3 (steps ±1); `[0x6f]` toggles 0..5; `if (y > 240) mode = 0`; glide `y -= 0.5/div` |
| 4 | every 40 frames: vx → +1; then same as mode 3 (vy → +3, `[0x6f]` toggle, y>240 reset); glide `y -= 0.5/div` |
| 0x7B (123) | drift mode: after 30 frames drag: `vx *= 0.95 if \|vx\|>2`, `vy *= 0.95 if \|vy\|>2`; after 50 frames: `mode = rand()%9+1`, and turn `vx = -vx` if `x > right-20` or `x < left+20` or `rand()%3==0`; no vertical glide this tick |

Notes: modes 1/2 preset -8.0 is written as a double through its high dword (upper = 0xC0200000,
lower = 0) - fish "darts". The glide subtraction (`y -= k/div`) is a constant-velocity component
on top of the vy integration.

### 5.4 Common tail (runs for every path)

- If `FUN_004da780()` == 0 → call virtual slot 81 (`*this+0x144`) - candidate: swim animation
  update (skipped while a food target exists).
- Dart counter `[0x82]`: if > 0 → decrement, `vy *= 0.9`.
- Knockback counter `[0x83]`: if > 0 → decrement, `v += v*0.9`... precisely:
  `tmp = this[+0x218]; [0x83]--; [+0x218] = tmp*0.9; x += tmp*0.9`.
- Counter `[0x84]`: if > 0 → decrement.
- Facing/sink ladder: exact-equality checks on vx rewrite the glide for this tick:
  `vx == 0.0 → y += 1.0/div; vx == 1.0 → y += 0.75/div; vx == 2.0 → y += 0.5/div;
  vx == 3.0 → y += 0.25/div` (integer "swim level" semantics; ties swim pose to slow sink).
- If `this[100]` (+0x190) `< 321` → `y -= 0.25` (small-tank drift-up).
- Clamps: `x ∈ [this[0x65], this[0x67]]`; `y ≤ this[100]`; floor `y ≥ this[0x66]` applied only
  when `[0x82] < 1 || vy <= 0`; otherwise (darting down, `[0x82] ≥ 31`) spawn burst FX:
  `FUN_00538ac0(x + (55 - rand%60), y + (55 - rand%60))` style emitters (radius 0x37 = 55;
  variant `[0x23]==6` uses 0x7d/0x69 = 125/105), probability gated by `rand % (2 or 1) == 0`
  and `rand` parity.
- Wall approach damping: if `x > right-5 && vx > 0.1` → `vx -= 0.1`; if `x < 15.0 && vx < -0.1`
  → `vx += 0.1` (hardcoded left 15.0).
- Call virtual slot 89 (`*this+0x164`) - candidate: animation frame advance.
- Integrate: `x += vx / div; y += vy / div` where `div = this[0x60]`, overridden to 0.3 / 0.8
  when `+0xF6 != 0` (state flag; +0xF8 picks which).
- Call virtual slot 41 (`*this+0xa4`) with one RNG-derived argument (candidate: periodic
  bubble/sound trigger).

### 5.5 Food approach path (feeding steering)

Entered when: not in attractor path AND slot 82() == 0 AND `FUN_004da780() != 0` AND
`manager+0x174 != 0` AND `+0x229 != 0`. (Candidate reading: hungry + a target exists.)

1. Walk the manager's entity list (helpers `FUN_004e5040/0x4e5010/0x4e3dd0/0x4e3e00/0x4e5070`)
   until an entity with `field+0x234 == 12` is found (otherwise an assert fires -
   `FUN_00564335`). The found entity is the **target**; its int x/y are at target+0x30/+0x34.
2. Horizontal steering on `dx = fish.x - target.x` (fish center offset cancels; clamps `|vx|<4`):

   | Δx (px) | Action |
   | --- | --- |
   | dx > +10 | `vx -= 1.3` (cap > -4) |
   | +5 < dx ≤ +10 | `vx -= 0.2` |
   | 0 < dx ≤ +5 | `vx -= 0.05` |
   | -5 ≤ dx < 0 | `vx += 0.05` |
   | -10 ≤ dx < -5 | `vx += 0.2` |
   | dx < -10 | `vx += 1.3` (cap < 4) |

   (Windows 0x32/0x1e/0x2d/0x23/0x28 = 50/30/45/35/40 in code; simplifies to the ±5/±10 dead
   bands above relative to target+40 vs fish+40.)

3. Vertical steering on `dy = fish.y - (food.y - 20)` (target aim = 20 px above the food;
   clamps: `vy < 4` below / `vy > -3` above):

   | Δy (px) | Action |
   | --- | --- |
   | dy > +5 | `vy -= 1.0` |
   | 0 ≤ dy ≤ +5 | `vy -= 0.5` |
   | -5 ≤ dy < 0 | `vy += 0.7` |
   | dy < -5 | `vy += 1.3` |

   (Exact code windows: `y+40` vs `food.y + 0x19/0xf/0x14` = 25/15/20, steps 0.7/-0.5/1.3/1.0.)
4. Floor: if `y_int ≤ this[0x66]` and `vy < 0` → `vy = 0`.
5. `[0x6f]` increments toward 5 (rhythm counter feeding slot 41 bubbles).

### 5.6 Attractor path (cursor/global)

When `DAT_005e89d0 != 0` AND `+0x229 != 0` AND `this[0x68] <= 1`: fish is moved **directly**
toward `(DAT_005e89d4, DAT_005e89d8)` (ints): dead zone ±5 (steps ∓3), band ±50 (steps ∓5 for
x, ∓4 for y), vx preset ±0.5 by facing, vy zeroed if `[0x82]==0`. Candidate: dragged
food/finger attractor - to be proven in P2.3. (Same globals gate the hover check in slot 26
with ±8.)

## 6. `Fish` slot 26 (0x4E4A90) - facing/hover + draw candidate

381 bytes; takes one argument (candidate: graphics/context param, propagated to the draw
helper). Behavior:

- `FUN_004d6ae0()` first (helper identity TBD).
- If global attractor active (`DAT_005e89d0 != 0`) and fish is within ±8 px of
  `(DAT_005e89d4, DAT_005e89d8)` and `+0x229 != 0` and `this[0x68] < 2`:
  set the double at `this[0x94]->+0x168` = **0** (hide) and return (when `this[0x94] == 0`,
  return directly). Otherwise set it to **1.0** (show) if the pointer exists.
- Facing dispatch: `f = this[0x71]` (+0x1C4):
  - `f > 0` → call virtual slot 83 (`*this+0x14c`)(arg, `this+0xF5 == 0`);
  - `f < 0` → same with `this+0xF5 != 0`;
  - `f == 0` → pick a side from vx vs thresholds `this[0x62]` (+0x188) with an RNG tiebreak,
    then call the same virtual.
- If `this[0x31]` (+0xC4) != 0 → `FUN_004e1400(arg, 0)` (extra draw layer).

Candidate reading: slot 26 = `Draw`-side method (draw body sprite with flip, plus an overlay
when +0xC4 is set), which also maintains the "cursor near fish → hide floating indicator"
behavior. Confirmation requires decompiling the slot-83 callee (the actual sprite draw) and
`FUN_004e1400` - both queued.

## 8. Implementation spec for P4 (preliminary - P2.2 still open)

Fish entity (Godot `Node2D` + script), pure-data update at fixed 100 Hz (P2.1):

- State: `pos: Vector2`, `vel: Vector2`, `swim_mode: int`, `mode_timer: int`,
  `random_switch_timer: int`, `target_timer: int` (0..5 oscillator), `dart_timer`,
  `knockback_timer`, `knockback_offset`, `facing: int`, `flip: bool`.
- Per tick:
  1. run hunger/target predicate (P2.3) → pick path: food-approach (steer to target point
     `food.pos + Vector2(0, -20)` with the ±5/±10 dead-band controller above), attractor path
     (cursor/finger), or swim mode machine.
  2. swim machine: apply preset vel + glide subtraction; 40-frame (0.4 s) steps; random re-roll
     every >20 frames at 10 % (→ ~2 s); mode 0x7B wall bounce ±20 px margins and 0.95 drag
     after 0.3 s.
  3. integrate `pos += vel / speed_divisor`; clamp to tank rect (fields +0x65/0x67/0x66/0x190).
  4. timers/decays for dart (vy*0.9), knockback, sink ladder for integer vx 0..3.
  5. facing: `facing` sign selects flip; if 0, choose by `vx` with RNG tie.
- Keep all constants as data (tunable) with module addresses in comments/export:
  mode constants (0.25/0.5 glide, -8.0 dash), steering (±1.3/±0.2/±0.05, ±1.0/0.7/-0.5),
  clamp bounds (±4 x, ±3/4 y), bounce margins (20), drag 0.95 (30/50-frame gates).
- The wall/bounds and speed divisor (`+0x180`) belong to tank geometry - finalize when P2.15
  (resources/tank sets) intersects.

Remaining for P2.2 to close: mode semantics certainty, slot 0/81/83/89 identities, `+0x68`
enum, species field, module tick-rate re-check. Then take stocks of turnout/facing visuals on
the real binary once (screenshot run) - optional playtest cross-check.
