# P2.11 - Game modes: Adventure, Time Trial, Challenge, Virtual Tank (+ Sandbox)

Status: COMPLETE (2026-10-29). Evidence: EV-0126-EV-0130. Raw evidence:
`p2.11-fn-54CBF0.json/.txt` (level-start orchestrator), `p2.11-fn-54CB20.json/.txt` (Virtual Tank
load-or-create), `p2.11-fn-53C3F0.json/.txt` (Virtual Tank init), `p2.11-fn-51B260.json/.txt`
(Virtual Tank fish spawner), `p2.11-fn-5498B0.json/.txt` (session init), `p2.11-fn-4D80C0.json/.txt`
(the `+0x19C` predicate), `p2.11-xrefs-4D80C0.json`, `p2.11-fn-46CCE0.json/.txt` (mouse-held bit),
`p2.11-fn-5404A0.json/.txt` (cosmetic option toggles).

Reused evidence (the tank update is the main source and was already on disk):
`p2.8-wave-block-547610.txt` (tank update: mode branches, banners, pressure clock), `p2.6-progression.md`
§10 (state model, store tables, rewards), `p2.5-economy.md` (price arrays, `SetStorePrice`),
`p2.2-game-module-strings.txt` (first-party help text).

All addresses are game-module VAs (D-0009). `Tank` = the tank-update `this`; the manager pointer is
`[this+0x8C]` in the tank update (elsewhere it is `[obj+0x88]`, as in P2.8); `Tank` = `[manager+0x730]`,
`profile` = `[manager+0x8B8]`, mode = `[manager+0x87C]`, tick counter = `Tank+0x444`,
tank index/level copies = `Tank+0x3C8`/`+0x3CC`.

## 1. The mode field

`[manager+0x87C]` is an int read by more than twenty sites across the tank update, the egg handler,
the store refresh, the alien/missile code and the level-start path. Values bound by behavior:

| value | mode | binding |
| --- | --- | --- |
| 0 | Adventure | `profile+0x1C/+0x20` drive tank/level; bonus round at tanks 1-3 (P2.6); banner "Here are your first fish!" (EV-0126) |
| 1 | Time Trial | timer + expiry branch (EV-0127); egg price 100; banner "How much money can you earn before time runs out?" |
| 2 | **unobserved** | no branch, string or behavior found (Q-0014 stays open) |
| 3 | Sandbox | money 999999; `profile+0xB4 = 11`; store re-roll (EV-0127); banner "Make sure caps-lock is off and GO TO TOWN!!" |
| 4 | Challenge | price inflation (EV-0127); composite aliens after 4 waves; challenge records; banner "Can you fend off the increasingly hungry aliens?" |
| 5 | Virtual Tank | `start_level` early-out + VT init (EV-0126/EV-0128); no alien wave clock; shells economy |

Bounded negative: **no writer of `[manager+0x87C]` exists in the committed decompiled corpus** (a
grep of `docs/evidence/*.txt` returns only reads). The menu that selects a mode is P2.12 material;
until it is decoded the remake's mode value is an input parameter, not a derived state.

`FUN_005404A0(option)` (EV-0126) is *not* a mode selector. It toggles cosmetic/PRNG options -
`Wavy Mode`, `Original Prego Sound`, `Original Breeder Sound`, `Ultra Prego Sound`, `Void Mode`,
`Space Mode` (also calls `FUN_00511580`) and `Zombie Mode` (`DAT_005e89ce`) - each printing an
"Enabled"/"Disabled" toast. Do not map these onto the mode enum.

## 2. Level start and Virtual Tank load (EV-0126)

```c
FUN_0054CBF0():                                  /* start_level */
    manager+0x883 = 0;
    if (mode == 5 && FUN_0054CB20() != 0) return;   /* resume an existing VT tank */
    FUN_0054C540();                                 /* fresh tank, sessions_started++ */
    FUN_00541A20();                                 /* tank init (P2.6 §10.2) */
    if (FUN_0054B2A0()) { FUN_00537E20(); FUN_0054B2D0(); return; }   /* tank complete */
    if (mode == 5) { FUN_0053C3F0(); FUN_0054B2D0(); return; }        /* VT init */
    FUN_005498B0();                                 /* normal session init */
    FUN_0054B2D0();                                 /* tank event */
```

`FUN_0054CB20()` is the Virtual Tank load-or-create path:

```c
FUN_0054C540();                                     /* fresh tank object */
FUN_00505880(path, mode, profile+0x44);             /* build a path from mode + profile+0x44 */
if (!FUN_00546AA0(path)) { FUN_0054BC30(); }        /* not found -> create */
else { manager+0x883 = 0; if (mode != 5) FUN_0054B3A0(); }
```

`profile+0x44` is therefore the **current Virtual Tank slot** (VT keeps more than one tank); the
two helpers `FUN_0054BC30` (create) and `FUN_0054B3A0` (load) are named by call site only. The
file itself is `sim%d.dat` (P2.13).

`FUN_005498B0()` (normal session init) is mode-agnostic apart from the tank switch: tank 4 spawns
through `FUN_005471E0` and marks the first fish `+0x1A4 = 2`; tank 5 sets `Tank+0x2C0 = 300` (a
300-tick wave clock instead of 3000) and spawns 18 pets (`FUN_00544A90`, indices 0..0x11); every
other tank spawns two starter fish through `FUN_00546EF0` and marks the first `+0x1A4 = 2`, with
`+0x228 = 1` on the tank-1 level-1 guppy.

## 3. Adventure (mode 0)

Everything in P2.6 §10 applies: `profile+0x1C/+0x20` select tank and level, the store sells fish,
upgrades and egg pieces, 3 egg pieces advance the level, tanks 1-3 run a bonus round, tank 5 is the
Cyrax level and tank 5 level 2 is the victory-gate state. Mode 0 also owns the tutorial banners:
tank 1 level 1 prints "Here are your first fish! Take good care of them!" and the following level
"On this level you will meet your 1st alien opponent!" - both at tick `0x96` (150), i.e. 4.2 s in.

Adventure also owns the tank-complete sentinel path: `profile+0x20 == 6` is the transient
"tank finished" state (P2.6) and `FUN_0054B2A0()` is the test `start_level` runs for it. That
function's body was not decompiled, so treat "which modes can reach it" as unproven - the other
modes complete through `Tank+0x2A5` (P2.6).

## 4. Time Trial (mode 1) - EV-0127

- Elapsed time is written to `Tank+0x3B0` **every tick** as `(FUN_00537B60() - Tank+0x3B8) / 1000`
  (integer seconds), and mode 4 writes the same field. `Tank+0x3B8` is the level start stamp;
  `Tank+0x3BC` is the budget.
- Budget: 300 s on tank 1, 600 s on tanks 2-4 (P2.6 §8).
- Expiry (`Tank+0x3BC - elapsed < 0`): clear `Tank+0x4EE`, `FUN_0053C2D0()` (collect all coins),
  `FUN_00514470()`, `FUN_0054EB80()` and return - the level ends in a results screen (the label
  "TIME TRIAL RESULTS" is at 0x5A26C0). Time Trial never reaches the egg-completion path through
  this branch, so the run ends by the clock, not by the egg.
- Store: egg price is forced to 100 (P2.6); pets are not offered (the pet branch requires
  `profile+0x59 == 0 || (mode != 1 && mode != 4)`, P2.6 §7).
- Reward: `Tank+0x3F0 * 5 / 100`, shown as "%d%% Bonus Award" (P2.6).
- The banner is "How much money can you earn before time runs out?" (first-party).

## 5. Challenge (mode 4) - EV-0127

- **Price inflation is real and in the binary.** While `Tank+0x454 < 1`, `Tank+0x43C < 6` (egg not
  complete) and one of the store item-present bytes `Tank+0x3A4` / `Tank+0x3A5` is set, the tank
  update runs every `period` ticks:

  ```c
  period = {150, 150, 175, 200}[tank_index - 1];          /* tanks 1..4 */
  if (tick % period == 0) {
      for (i = 0; i < 12; i++) {
          price_B[i] = min(price_B[i] + increment_D[i], 99999);   /* +0x314[i] += +0x374[i] */
          FUN_00534380();                                   /* store object refresh */
      }
  }
  ```

  So Challenge inflation is a per-item `price += increment` on the same arrays the store UI draws
  (P2.5 §3), capped at 99,999, and faster on the later tanks. The asset/spec consequence: the
  inflation rate is a function of tank index only, not of level or of elapsed time.
- **Alien difficulty** comes from the wave type sets and one substitution: in mode 4, when the wave
  counter `Tank+0x45C` is greater than 4 and the rolled type is `8` (Bilaterus), the type is
  replaced by `0xC` (the Balrog+Bilaterus composite). No hp or speed multiplier exists in the mode-4
  branch, so "increasingly difficult aliens" is type selection, not stat scaling.
- Completion writes the challenge unlock byte `profile+0x77+tank = 1` and the record block
  `profile+0x34+(tank-1)*12` (P2.6), then shows the challenge results screen (label
  "CHALLENGE RESULTS", 0x5A26D4). Reward is a flat 2000/5000/10000/20000 for tanks 1-4.
- Banner: "Can you fend off the increasingly hungry aliens?".

## 6. Sandbox (mode 3) - EV-0127

- `Tank+0x3F0 = 999999` at level start and `profile+0xB4 = 11` (P2.6).
- The tank update re-rolls store prices while the tank is not 5 and `Tank+0x2E0 < Tank+0x2DC`:
  twelve `FUN_005409B0()` calls (per-item refresh) followed by `FUN_005380C0()` =
  `SetStorePrice` (P2.5, one of its three call sites). This is the "random store" of Sandbox; the
  exact randomisation lives inside `SetStorePrice`, not in the update.
- Banner: "Make sure caps-lock is off and GO TO TOWN!!".
- Sandbox is the only mode observed reading `Tank+0x2DC/+0x2E0` as a comparison pair; their meaning
  is not bound (Q-0024).

## 7. Virtual Tank (mode 5) - EV-0128

Entry: `start_level` returns through `FUN_0054CB20` (resume) or `FUN_0053C3F0` (fresh), never
through `FUN_005498B0`, so no aliens are armed and no starter fish are spawned by the normal path.

`FUN_0053C3F0()` (VT init) resets the tank for a virtual session:

```c
Tank+0x2BC = 0;  Tank+0x94 = 0;  Tank+0x4EE = 1;
DAT_005e89dc = 0;  DAT_005df58c = 1;  DAT_005e89cc = 0;  DAT_005e89d0 = 0;  DAT_005e89c0 = 0;
Tank+0x440 = 0;  Tank+0x444 = 0;  Tank+0x450 = 0;  Tank+0x454 = 0;  Tank+0x458 = 0;  Tank+0x45C = 0;
Tank+0x3B4 = Tank+0x3B8 = now();  Tank+0x4FC = <incoming byte>;
FUN_005394E0();   /* populate the VT tank */
FUN_0053A4F0();   /* VT store       */
FUN_0053AA00();   /* VT HUD/anchor  */
```

- **No aliens.** The tank-update branch `mode == 5 && Tank+0x4FE == 0` jumps over the entire wave
  clock, so a VT session has no alien counters, no wave re-roll and no pressure clock. `+0x4FE`
  (P2.8's "warning sound enable") is the switch; its writer is unbound (Q-0020). A VT session that
  *does* want aliens would have to set that byte - treat it as an unknown, not as a feature.
- **Fish spawner** `FUN_0051B260(param_1, excluded_type)`: with probability 76 % (`rand() % 100 <
  0x4C`) it spawns an ordinary fish via `FUN_00519E00()` (and with 76 % again upgrades it through
  `FUN_00519890(obj, 1)`), otherwise it rolls a prize fish from this weighted table:

  | weight | type id | alloc | spawn helper |
  | --- | --- | --- | --- |
  | 26 | 8 (Penta) | 0x1B0 | `FUN_004EC0F0` |
  | 25 | 9 (Grubber) | 0x1B0 | `FUN_004EA7B0` |
  | 25 | 7 (Gekko) | 0x230 | `FUN_004EF9A0` |
  | 10 | 10 (Breeder) | 0x1E0 | `FUN_004EE530` |
  | 5 | 6 (Ultra) | 0x230 | `FUN_004F02A0` |
  | 3 | 0x24 (BiFish) | 0x238 | `FUN_004F0630` + `+0x230 = rand() & 1` |
  | 3 | 0x23 (BallFish) | 0x230 | `FUN_004F0570` |
  | 3 | 0x22 (SylvesterFish) | 0x230 | `FUN_004F01E0` |

  Type ids are the P2.4 roster (EV-0044/EV-0056); the helpers are named by call site only. Because
  the weights sum to exactly 100 and the test is a strict `<`, the fallback index 8 is unreachable
  and the default (`type == 5`, Oscar) shares the Penta branch at `FUN_004EC0F0`. If the rolled type
  equals `excluded_type`, or `FUN_005195E0()` returns 0, the function retries up to 100 times and
  then recurses with `excluded_type = -1` (the "give me anything" call).
- **Shells.** The VT currency is the same `Tank+0x4A8` counter and `FUN_0053C1E0` routing used by
  the bonus round (P2.6 §9); mode 5 sends the payout to `profile+0x48` plus `Tank+0x400`.
- **First-run hint.** At tick 150 in mode 5 with `profile+0x48 == 0` the tank prints "Here you'll be
  able to build your own custom fish tank!" (`FUN_0041D8B0` + `FUN_0053E950`).
- **Help text (first-party, 0x5A3CBC-0x5A44F0)** states the design contract the code must match:
  fish cannot die or be killed; fish grow in about a real-world week if fed daily; fish want to eat
  three times a day and become unhappy otherwise; the store changes daily with the real date; the
  tank can be set as the screensaver from the Tank screen; the Pets/Fish screens configure the
  display, hide/show and sell fish.

## 8. Rapid Fire, found in the tank update (answers Q-0023's last item) - EV-0129

`FUN_00543920` only *arms* the auto-fire: the click handler sets the byte `Tank+0x4ED = 1` and
stamps `Tank+0x3C4 = now()`. The tank update owns the repeat:

```c
if (Tank+0x4ED != 0) {
    if ((Tank+0xEC & 1) == 0) Tank+0x4ED = 0;                 /* mouse released -> disarm */
    else if (Tank+0x3E4 > 0xB                                    /* weapon level 12+ */
          && tick % (0xB - Tank+0x3E4 / 2) == 0                  /* 5 ticks at level 12 */
          && now() > Tank+0x3C4 + 100                            /* 100 ms between shots */
          && click_y > 0x28) {
        for each in Tank+0xF4: Missle::HitTest(x, y);
        for each in Tank+0xDC: Larva::HitTest(x, y);
        for each in Tank+0xB8: Alien::HitTest(x, y);
        FUN_00543640();  FUN_00538AE0();                          /* spark + hit bookkeeping */
    }
}
```

- `FUN_0046CCE0()` is `return *(byte *)(this + 0xEC) & 1`, so `Tank+0xEC` bit 0 is the tank's
  mouse-button latch (EV-0129).
- The repeat order is **missiles -> larvae -> aliens**, i.e. the reverse grouping of the click
  handler; the boss, the `Tank+0xBC` list, the bonus round and the feed path are not repeated.
- At level 12 the period is `11 - 6 = 5` ticks (about 139 ms at 36 Hz), so the 100 ms stamp is the
  real limiter; above level 12 the period shrinks by one tick per two levels (unreachable: the cap
  is 12).
- Auto-feed uses the same latch pattern with `Tank+0x4EC` and `Tank+0x13B` (P2.3).

## 9. Correction: `FUN_004D80C0` is not the demo flag - EV-0130

```c
int FUN_004D80C0(void) {
    int v = *(int *)(this + 0x19C);
    return (v == 3 || v == 4 || v == 5);
}
```

Eleven call sites (`p2.11-xrefs-4D80C0.json`), all in the object/alien/missile code. The receiver is
the caller's `this`, so the predicate means "**this object's `+0x19C` is 3, 4 or 5**".

- For `Sexy::Missle`/`Sexy::Larva`, `+0x19C` is the kind (`in_ECX[0x67]` in the ctor), so the
  predicate is `kind in {3,4,5}`. The known spawn sites only create kinds 0 and 1 (Destructor,
  Ulysses), so the missile ctor's random-velocity branch and the kind-3+ bounds rule are
  **unreachable in retail play**. The earlier "demo" label (P2.10 §0/§5.2) is withdrawn: the
  real demo flag is `manager+0x880`, which is a different field.
- For `Sexy::Alien`, `+0x19C` is a *byte* flag (Psychosquid's "already slept once", P2.9 §6), so the
  dword compare there is a different field interpretation - do not port the predicate to aliens.
- Consequence for the remake: missiles always start still and are steered by `FUN_004FF4E0`; there
  is no random-velocity missile in normal play; the victim pointer `target+0x98` is always set when
  the spawner creates a missile from an alien.

## 10. Implementation spec for P4

1. **Mode is input, not state.** Pass the mode (`0..5`, 2 unused) into the level-start routine; do
   not derive it. Keep every mode branch in one place (a `mode_rules` table) because the binary
   spreads them over eight functions.
2. **`start_level` order**: fresh tank -> tank init -> tank-complete sentinel -> VT branch or normal
   session init -> tank event. Mode 5 must not run the normal session init (no starter fish, no
   alien clock).
3. **Time Trial**: budget 300 s (tank 1) / 600 s (tanks 2-4); elapsed seconds tick every frame;
   expiry collects all coins, ends the level and shows the results screen; egg price 100; no pets;
   reward `money * 5 / 100`.
4. **Challenge**: `price[i] = min(price[i] + increment[i], 99999)` every 150/150/175/200 ticks for
   tanks 1-4 while the egg is incomplete; rolled alien type 8 becomes 0xC after wave 4; flat
   completion reward 2000/5000/10000/20000; unlock byte + record block per tank.
5. **Sandbox**: 999999 starting money, `profile+0xB4 = 11`, per-frame price re-roll through the
   store-price setter, no tank-5 case.
6. **Virtual Tank**: load-or-create `sim%d.dat` keyed on `profile+0x44`; reset block from
   `FUN_0053C3F0`; populate, store, HUD; fish spawner 76 % ordinary / 24 % weighted prize table
   (26/25/25/10/5/3/3/3) with an exclusion type and a 100-try retry; no aliens unless
   `Tank+0x4FE` is set (unknown writer); shells via `Tank+0x4A8` + `FUN_0053C1E0`.
7. **Rapid Fire**: arm on click (`Tank+0x4ED`), disarm when the mouse-button bit clears, fire while
   `weapon_level > 11` every `11 - level/2` ticks but not more often than 100 ms, in the order
   missiles -> larvae -> aliens, spark per shot. No boss/feed repetition.
8. **Keep the mode-2 row empty** and the `Tank+0x2DC/+0x2E0` pair and the `+0x4FE` writer
   parameterised (Q-0024).
9. **Do not port `FUN_004D80C0` as "demo"** - it is an object-kind test (Q-0024).
