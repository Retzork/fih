# P2.14 - Audio system (BASS music, DirectSound effects, mixing)

Status: **complete** (2026-11-01), with the tracked open items Q-0030/Q-0031. Target: game module
`docs/analysis/snapshots/insaniquarium-game-module.exe` (D-0009). All VAs are game-module VAs.
Evidence: EV-0145..EV-0149 (this pass). Engine identity from EV-0009/EV-0013.

## 1. What the binary actually contains

Three audio layers sit in the module, and only one of each is live:

| Layer | Class (RTTI) | Vtable | Slots | Role |
| --- | --- | --- | --- | --- |
| SFX manager (abstract) | `Sexy::SoundManager` | `0x5C1084` | 18 | interface; only slot 0 is real (dtor `0x495330`), the rest are `0x5693CF` stubs |
| SFX manager (concrete) | `Sexy::DSoundManager` | `0x5C1104` | 18 | DirectSound: owns the slot pool, loads, plays and mixes every sound effect |
| SFX instance | `Sexy::DSoundInstance` | `0x5C10D0` | 12 | one voice (volume, pan, pause, stop) |
| Sound resource layer | `Sexy::SoundRes::ResourceManager` | `0x5B0470` | 2 | name -> SoundManager slot id, decode, `cached\` cache |
| Music (abstract) | `Sexy::MusicInterface` | `0x5C1164` | 20 | body slots are stubs (`0x46C690`/`0x486BF0`) |
| Music (BASS) | `Sexy::BassMusicInterface` | `0x5C11BC` | 20 | the shipped, used music backend (`.mo3` through BASS) |
| Music (FMOD) | `Sexy::FModMusicInterface` | `0x5C1214` | 22 | compiled in, dead on this build (no `fmod.dll`) |
| BASS wrapper | `Sexy::BASS_INSTANCE` | `0x5C1158` | 1 | `LoadLibrary(".\\bass.dll")` + one function pointer per BASS entry |

- The install ships `bass.dll` (SHA-256
  `d98cd5d6ed9c4a95701684aa83777cefd5d8096e14c836493f67159d68161c01`, EV-0001/EV-0004) and no
  `fmod.dll`, so `BassMusicInterface` is the live music backend; `FModMusicInterface` and the
  `_FSOUND_*` name table (`"%s function not found in fmod.dll"`, `0x5C0A48`) are dead code kept
  from the shared PopCap framework static library.
- Sound effects do **not** go through BASS. They go
  `SoundRes::ResourceManager` -> `Sexy::DSoundManager` -> `IDirectSoundBuffer`. DirectSound is
  bound **dynamically**: the static import table has no `dsound.dll` (EV-0011: 10 system DLLs, no
  `ddraw`/`dsound`), and the `DSoundManager` constructor resolves `DirectSoundCreate` with
  `GetProcAddress(<module>, "DirectSoundCreate")` on a handle loaded from the literal `dsound.dll`
  string (the module also keeps `DSound Ver: ` for a version log line).
- Music is mixed by BASS on its own device; SFX are mixed by DirectSound. That is why the two
  volume settings are independent (§6).

## 2. The BASS wrapper

`FUN_00498010` (1434 B) is `Sexy::BASS_INSTANCE`'s loader: it stores its vtable at `+0x0`, calls
`LoadLibraryA(".\\bass.dll")` (string `0x5C0A18`) into `+0x4`, then `GetProcAddress` for every name
in the `.rdata` table at `0x5C0608..0x5C0A04`, storing each pointer at a fixed dword index.
Failure paths:

- library missing -> `FUN_00498690` (89 B) reports `"Can't find bass.dll."` (`0x5C0A24`);
- one entry missing -> `FUN_00497FA0` reports `"%s function not found in bass.dll"` (`0x5C05DC`);
- **both** `BASS_SetGlobalVolumes` and `BASS_SetVolume` missing is fatal ->
  `MessageBoxA(0, "Neither BASS_SetGlobalVolumes or BASS_SetVolume found in bass.dll", "Error",
  MB_ICONHAND)` then `_exit(0)`.

Field map (dword indices as the decompiler prints them, byte offset `4*n`; `[0]` vtable, `[1]`
`HMODULE`, `[2]` = `SetConfig`-present byte at `+0x08`):

| n | entry | n | entry | n | entry |
| --- | --- | --- | --- | --- | --- |
| 3 | `BASS_GetVersion` | 16 | `BASS_ChannelPlay` | 30 | `BASS_ChannelGetData` |
| 4 | `BASS_Init` | 17 | `BASS_ChannelPause` | 32 | `BASS_ChannelSetSync` |
| 5 | `BASS_Init` (2.0 alt) | 18 | `BASS_ChannelSetAttributes` | 33 | `BASS_ChannelRemoveSync` |
| 6 | `BASS_Free` | 19 | `BASS_ChannelGetAttributes` | 34 | `BASS_MusicLoad` |
| 7 | `BASS_Stop` | 20 | `BASS_ChannelSetPosition` | 35 | `BASS_MusicLoad` (2.0 alt) |
| 8 | `BASS_Start` | 21 | `BASS_ChannelGetPosition` | 36 | `BASS_MusicFree` |
| 9 | `BASS_SetGlobalVolumes` | 22 | `BASS_ChannelSetFlags` | 37 | `BASS_StreamCreateFile` |
| 10 | `BASS_SetVolume` | 23 | `BASS_ChannelIsActive` | 38 | `BASS_StreamFree` |
| 11 | `BASS_GetVolume` | 24 | `BASS_ChannelSlideAttributes` | 39 | `BASS_FXSetParameters` |
| 12 | `BASS_GetInfo` | 25 | `BASS_ChannelIsSliding` | 40 | `BASS_FXGetParameters` |
| 13 | `BASS_SetConfig` | 26 | `BASS_ChannelGetLevel` | 41 | `BASS_MusicGetAttribute` |
| 14 | `BASS_GetConfig` | 27 | `BASS_ChannelSetFX` | 42 | `BASS_MusicSetAttribute` |
| 15 | `BASS_ChannelStop` | 28 | `BASS_ChannelRemoveFX` | 43 | `BASS_MusicGetOrders` |
| | | 29 | `BASS_ChannelGetLength` | 44 | `BASS_MusicGetOrderPosition` |
| | | 31 | `BASS_ChannelPreBuf` | 45 | `BASS_PluginLoad` |
| | | | | 46-52 | `SampleLoad`, `SampleFree`, `SampleSetInfo`, `SampleGetInfo`, `SampleGetChannel`, `SampleStop`, `ErrorGetCode` |

When `BASS_SetConfig` is present (the shipped `bass.dll` exports it - the presumed BASS 2.0
layout) the wrapper moves `[4]`->`[5]` and `[34]`->`[35]` (byte `+0x08` = 1) and *clears* `[4]`
and `[34]`, i.e. the 2.0 call sites use the alternate indices 5/35 and the legacy indices stay
null. The three extra 2.0-only names (`ChannelGetLength`, `ChannelPreBuf`, `PluginLoad`) are
resolved only on that path.

## 3. Music: three tracks, ids 1/3/4, preloaded at startup

`FUN_005503C0` (`SexyApp::Init`, `0x5503C0..0x550F9x`) builds the game manager and the title
screen, then **preloads all three music files** through the music interface at `app+0x374`
(`[in_ECX + 0xDD]`), vtable slot **1**, signature `(int trackId, const std::string& fileName)`:

| trackId | file | length (P3.7) | use |
| --- | --- | --- | --- |
| 1 | `music\Alien.mo3` | 10.24 s | alien battle |
| 3 | `music\Lullaby.mo3` | 115.70 s | calm / menu-ish |
| 4 | `music\Insaniq2.mo3` | 113.66 s | main "Winfish" theme |

Ids 0 and 2 are never loaded (`0` = none, `2` = reservation for the bonus/level-complete state -
see §4.2); the three load calls are emitted back to back at `0x550F10..0x550F5F`
(`docs/evidence/p2.14-decompile-550E53.txt`).

### 3.1 Which music interface the app builds

`FUN_00488300` is the music-interface factory called from app init. It allocates exactly one of
three objects, in this precedence order:

| Guard | Alloc | Class | Effect |
| --- | --- | --- | --- |
| `app+0xF0 != 0` | 4 B | `Sexy::MusicInterface` (`FUN_0049B2A0`) | null backend: every slot stub -> **music silent** |
| else `app+0xF1 != 0` | 0x20 B | `Sexy::FModMusicInterface` (`FUN_00499DD0`) | FMOD; needs `fmod.dll`, not shipped |
| else | **0x18 B** | `Sexy::BassMusicInterface` (`FUN_00498750`) | **live path on this build** |

`app+0xF0`/`app+0xF1` are the "no sound" and "prefer FMOD" switches. Which user-visible option or
command line sets them is not bound (Q-0031).

### 3.2 `BassMusicInterface` slot 1 = `LoadMusic(trackId, fileName)` - `FUN_00498A00`

1. If the name contains no `.` (`FUN_004226C0(name, 0x2E) == -1`) the name is treated as a stem
   and three extensions are probed in order - `wav`, `ogg`, `mp3` (`0x5C0A3C/40/44`) - via
   `FUN_00422860(0, name, ext, 3)`. `music\Insaniq2.mo3` carries `.mo3`, so **the probe list
   contains no `mo3`**: an extension-less module name would never resolve.
2. A `.mo3` name takes the **memory path**: `FUN_00495420` opens the file, `FUN_004954F0` sizes
   it, `alloc(size)`, `FUN_00495520` reads it whole, then
   `BASS_INSTANCE[34](mem=1, buffer, 0, 0, flags)` = `BASS_MusicLoad(mem=1, ...)`, followed by
   `BASS_INSTANCE[8/7]` stop/start bookkeeping and the buffer free. `flags` is loaded from the
   interface field `+0x14` (value not proven - Q-0031; the `& 4` bit would be `BASS_SAMPLE_LOOP`).
3. Otherwise the track is registered in the interface's `std::map` keyed by track id
   (`FUN_0049B5E0` is a red-black-tree find/insert).

### 3.3 `BassMusicInterface` slot 2 = `PlayMusic(track, position, flag)` - `FUN_00498D10`


Looks the track node up in the map, then on a *different* node than the current one:
`node+0x20 = node+0x30`, `node+0x28 = 0`, `node+0x38 = flag`, `BASS_INSTANCE[18]`
(`ChannelSetAttributes`) on the node's music handle (`+0x18`, falling back to the stream handle
`+0x1C`), `BASS_INSTANCE[15]` (`ChannelStop`), then `FUN_00498620(position, 4 | 0x8200)` - i.e.
restart with loop bit `4`, or `4` when the 2.0 layout is detected - and finally
`FUN_00498670(position != -1)` plus, when `position > 0`, `BASS_INSTANCE[20]`
(`ChannelSetPosition`) = seek to that order. So the interface is
"load once, then play/seek an already loaded module, looping".

### 4.2 `FUN_0054B090` - the optional remap

Gated on `DAT_005e28cc != 0`. It rewrites the pair before playback:

| input (a, b) | output (a, b) |
| --- | --- |
| (0, 0x16 = 22) | (4, 0) |
| (0, 0) | (4, 0xC = 12) |
| (0, 0xD = 13) | (4, 0x3A = 58) |
| (2, 0x20 = 32) | (4, 0x19 = 25) |
| (2, 0x2D = 45) | (4, 0x25 = 37) |

## 6. Volume model and the options

`FUN_0047EDA0` = `SexyAppBase::ReadUserConfig`, `FUN_0047E280` = `SexyAppBase::WriteUserConfig`.
Both use the registry key at `app+0x7C` and the same names:

| Option (`string VA`) | Stored | App field | Conversion |
| --- | --- | --- | --- |
| `MusicVolume` (`0x5BF63C`) | integer percent | `app+0xD0` (**double**) | read `pct / 100.0`; write through `ftol` |
| `SfxVolume` (`0x5BF648`) | integer percent | `app+0xD8` (**double**) | same |
| `Muted` (`0x5BF654`) | integer | `app+0x428` | write emits a *derived* value from the dwords at `app+0x428`/`app+0x42C` (`A != B && A - B > 0`, i.e. `A > B`); `app+0x42C` has no reader of its own (Q-0031) |
| `ScreenMode`, `PreferredX`, `PreferredY`, `CustomCursors`, `WaitForVSync`, `InProgress`, `RegistryKey`, `Buffer` | - | - | other options in the same block |

Both volumes are **doubles in 0..1** in memory and **integer percent 0..100 in the registry**, and
they are independent because music and SFX are mixed by two different engines (§1). The Options
dialog's two sliders (ids 5/6) are seeded from app vtable slots `0xE0`/`0xE4` = the music/SFX
volume getters (P2.12 §11.3, EV-0136/EV-0137).

## 7. SFX load path, slot pool and mixing

### 7.1 The slot pool

`Sexy::DSoundManager`'s constructor `FUN_00495590(this, HWND, byte)` - called from
`SexyAppBase::Init` `FUN_004883F0` at `0x488CE7` with `app+0x350` (the window handle) as second
and `*(byte*)(app+0xF1)` as third argument, guarded by `cmp [app+0xF0], 0` - does:

- `_eh_vector_constructor_iterator_(this+0x404, 0x1C, 0x100, ...)`: **256 slot records of 28
  bytes** at `+0x404`;
- a parallel **256-entry volume array** of doubles at `+0x2408`, every entry initialised to
  `1.0` (`0x3FF0000000000000`), and a 256-dword array at `+0x2C08` cleared;
- `DirectSoundCreate(0, &this->ds, 0)` (default device) via `GetProcAddress`,
  `IDirectSound8/SetCooperativeLevel(hwnd, 2)` with a fallback to `1` when it fails, then a
  **primary buffer** through `IDirectSound::CreateSoundBuffer` from a `WAVEFORMATEX`-shaped stack
  block (raw dwords `0x100004`, `0x14`, `1`, `0`, `0x12`, `0`) and a `SetFormat` on it.

So the mixing model is a fixed pool of **256 sound ids**, each with its own volume; playing is
"take the slot's cached buffer, hand it to a `DSoundInstance`, play".

### 7.2 Loading a sound

`FUN_00419320` (339 B, `SoundRes`'s per-record loader):

```
i = soundManager->vtable[16]()                     ; 0x496D10  GetFreeSoundId()
if (i < 0) { report "Out of free sound ids"; throw }
else if (!soundManager->vtable[3](i)) {            ; 0x496720  LoadSound(slot)
  report "Failed to load sound: %s"
} else {
  if (0 < record->volume /* +0x70 double */) soundManager->vtable[6](i, volume);  ; 0x496D70
  if (record->pan /* +0x78 int */)           soundManager->vtable[7](i, pan);     ; 0x496D90
  record->soundId /* +0x6C */ = i;
  this->vtable[13]();                              ; notify
}
```

A sound resource therefore carries a default volume (double `+0x70`) and a pan/priority int
(`+0x78`); the manager hands out ids from the 256-slot pool and the `SoundRes` layer can also
cache decoded sound into `cached\` (strings `RIFF/WAVE/fmt /dep /xor /data`, `.snd`, `.wav`,
`cached\`, `0x5C0554..0x5C05A4`; the cache format itself is not decoded - not needed for P4).

`Sexy::DSoundManager` slot 17 (`0x496D30`) returns the occupied-slot count - that is the
`"Num Sounds: %d"` line of the video-stats overlay `FUN_00483A20`, which reads the manager at
`app+0x4B4`.

### 7.3 Playing a sound

`SexyAppBase` vtable slot `0xD8` = `FUN_004896B0(int soundId)` - the only sample entry the game
uses:

```
if (app+0x4B4 /* SoundManager */) {
  inst = soundManager->vtable[8](soundId);   // 0x4976F0  GetSoundInstance / PlaySound
  if (inst) inst->vtable[7](0, 1);           // 0x497E10  Play
}
```

So a game-side `PlaySample` passes **only the id** (no per-call volume or pan); the voice starts
with the slot's volume and the `(0, 1)` pair of `DSoundInstance`.

### 7.4 The sound table: every `SOUND_*` name -> a global id

The startup loader stores each resource's allocated id into a dedicated global dword. All 65 are
extracted (`docs/analysis/inputs/p2.14-sound-table.txt`; engine-free scan for
`push "SOUND_x"` ... `mov [global], eax`, cross-checked against the Ghidra decompile of the same
function). Examples: `SOUND_BUTTONCLICK -> 0x5E8C40`, `SOUND_BUY -> 0x5E8D14`,
`SOUND_HATCH -> 0x5E8D44`, `SOUND_DIE -> 0x5E8A70`, `SOUND_TONELO -> 0x5E8A3C`.

Gameplay reads those globals and passes the value to slot `0xD8`. Direct read sites were scanned
for all 65 (`docs/analysis/inputs/p2.14-sound-id-xrefs.txt`): **33 of 65 have a direct
`mov reg,[global]` / `push [global]` site**, the rest are reached through encodings the scan does
not cover. Mapping every id to its gameplay event is Q-0030 (tracked, non-blocking: P4 triggers
sounds from the same places the other P2 notes already describe).

## 8. Implementation spec for P4

1. **Two independent mixers.** Music and SFX never share a bus in the original. In Godot use two
   `AudioStreamPlayer` buses - `Music` and `Sfx` - and reproduce the two-part volume model of §6
   (0..1 doubles in memory, percent integers in the config file).
2. **Music assets.** Use the P3.7 OGG transcodes (`assets_raw/music/{Alien,Insaniq2,Lullaby}.ogg`).
   Load all three up front at startup (as `SexyApp::Init` does) and never stream from disk mid-level.
3. **Looping.** The play slot restarts the module with the loop bit (`4`) and can seek by order
   (`ChannelSetPosition`), so: `loop = true` on every track and treat `SetMusic`'s `b` value as a
   *start position*, not a duration. The exact unit of `b` is open (Q-0031b); starting at 0 is
   safe because no observed level-play call depends on a non-zero seek.
4. **Track selection.** Port §4.1 as data:
   `stage 1 -> (0,22)`, `stage 2 -> (0,0)`, `stage 3 -> (2,32)`, `stage 4 -> (2,45)`,
   `level complete -> (0,13)`, `startup/screens -> (2,45)` / `(2,54)`.
   Which loaded file each pair resolves to is **not** proven (Q-0031b) - the safest P4 mapping is
   to keep the three tracks and pick per context by ear against the original (the 10 s `Alien`
   module is unmistakably the battle loop, and it is the one track that must not loop over menu
   screens). The remap table of §4.2 is not ported unless `DAT_005e28cc` turns out to be a
   shipped mode.
5. **Virtual Tank plays no music** (§4.1). Reproduce that.
6. **SFX.** Load all 65 sounds from `properties\resources.xml` at session start into a fixed pool
   (256 slots is the original's cap; 65 sounds x a handful of concurrent voices is well inside
   it). A play call is "id only": use the resource's default volume/pan from §7.2 and let a voice
   play to completion; no per-call volume from gameplay.
7. **Overlap.** `SoundInstance`-style: one shot can overlap itself (the tank fires the same click
   sound repeatedly). Model a `SfxPool` autoload that takes `(id, volume, pan)` and allocates a
   free player from the pool; drop the play (and log) when the pool is exhausted, mirroring
   `"Out of free sound ids"`.
8. **Options.** Two sliders 0..100 -> `MusicVolume`/`SfxVolume` percent, applied to the two buses;
   persist them next to the other options (§6). Volume application must be instant (the original
   sets the attribute immediately on every live channel).
9. **Not needed:** BASS, `.mo3` decoding, the `cached\` sound cache, the FMOD path, the
   video-stats overlay.
10. **Do not port:** the `_FSOUND_*`/BASS name table, `BASS_ChannelPreBuf` (2.0-only branch), and
    the `dsound.dll` dynamic loader - Godot supplies its own mixer.
