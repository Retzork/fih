## 1. Lifecycle

### 1.1 Level start (normal)

`FUN_0054CBF0` is the level-start orchestrator (EV-0068):

1. clear `manager+0x883`; mode 5 (`manager+0x87C`) may early-out through `FUN_0054CB20`;
2. `FUN_0054C540`: allocate a fresh 0x504-byte tank object, run ctor `FUN_00542150`, store at
   `manager+0x730`, add to the list at `manager+0x320`, and increment `profile+0x4C` (level
   sessions/tank instances started). This runs at **every** level start, so the previous Tank
   object is replaced and the new one starts from the current profile values. The ctor clears
   `Tank+0x2A5` and `Tank+0x4EE`, so a fresh tank cannot re-finalize a previous one (EV-0072);
3. `FUN_00541A20`: tank init - copy tank/level into `Tank+0x3C8/+0x3CC`, set money, reset item
   arrays, call the store initializer `FUN_00541200` and create the 12 store items (SS2, EV-0061/
   EV-0072);
4. `FUN_0054B2A0` (tank-complete sentinel) true -> `FUN_00537E20` (finalizer) + `FUN_0054B2D0`
   (tank-complete event); **no** session init;
5. mode 5 -> `FUN_0053C3F0` + `FUN_0054B2D0`;
6. otherwise `FUN_005498B0` (session init) + `FUN_0054B2D0`.

Gameplay then runs: store purchases, egg pieces, aliens/waves (SS8). `Tank+0x43C` starts at 1
(tank 5: 3) and increments per egg-piece purchase; reaching 4 completes the level (three
purchases; one on tank 5) (EV-0064/EV-0072).

### 1.2 Level completion (`FUN_00545960`, EV-0067)

Before branching the handler records `Tank+0x3FC = FUN_00538040()` (elapsed seconds), clears
`Tank+0x4EE`, and collects every floor coin with `FUN_0053C2D0`. Branches:

- **Mode 4 (Challenge):** set `profile+0x77+tank = 1` for tanks 1-4, call
  `FUN_005144C0(tank, profile, Tank+0x3FC)` to write the Challenge record, then
  `FUN_0054BF60` (BonusScreen). No level advance (the challenge run ends at the tank's boss).
- **`profile+0x59 != 0` (Bonus Adventure):** tank 5 + level 1 -> `FUN_00501370` then
  `FUN_0054BF60` directly (no pet/hatch); every other level -> `FUN_0053DC10` fast path
  (SS6.4).
- **Normal Adventure:** `FUN_00501370` advances `profile+0x1C/+0x20`; then the award is
  computed from the **completed** level copies in `Tank+0x3C8/+0x3CC` (EV-0076):
  tank 5 -> index 19 (Presto); tank 4 + level 5 -> special card 999 with **no grant**;
  otherwise `index = tank*5 - 6 + level`. `FUN_00501420(index, 1)` grants the pet; index 19 also
  adds 5000 Shells (`FUN_00501200`); `FUN_0054BE80(index)` opens the HatchScreen.

### 1.4 Level 5 -> level 6 sentinel -> bonus -> next tank (EV-0068)

On a normal level-5 completion the advance writes `profile+0x20 = 6`. After the HatchScreen and
pet selection, the next `FUN_0054CBF0` sees the sentinel and runs the finalizer instead of
session init:

- `FUN_00537E20` (Tank finalizer): clears the overlay at `[Tank+0x118]+0xD0`; `+0x2A8 =
  +0x444`; `+0x2BC = 0`; `+0x94 = 0`; `+0x2A5 = 1`; `+0x2A4 = 0`; clears globals
  `DAT_005e89dc`, `DAT_005e89cc`, `DAT_005e89d0`, `DAT_005e89c0`, sets `DAT_005df58c = 1`;
  clears `+0x440/+0x450/+0x454/+0x45C/+0x458`; sets `Tank+0x3BC` (bonus duration, SS6.1);
  `+0x3F4 = +0x3F8 = 0`; `+0x2AC = -1`; `+0x2B0 = 0`; `+0x3B4 = +0x3B8 = now`.
- `FUN_0054B2D0` (tank-complete event; mode 5 skipped): level-6 sentinel -> `FUN_0054B1A0(0,
  0xD, 0)`; otherwise tank 1 -> `(0,0x16)`, tank 2 -> `(0,0)`, tank 3 -> `(2,0x20)`, tank 4 ->
  `(2,0x2D)`, tank 5 -> none.
- `FUN_00547610` (tank update) runs the two-stage transition: when `+0x2A5 != 0 && +0x2A4 == 0`
  and `+0x444-+0x2A8 > 0x9F` (160 frames), `FUN_00537F40` starts the bonus (`+0x2A4 = 1`,
  resets `+0x3B4/+0x3B8`, `+0x3B0 = 0`, `+0x2A8 = +0x444`). Once the bonus timer
  `+0x3BC-(now-+0x3B8)/1000 < 0`, the coin list `Tank+0xA8` is empty and the old `+0x3F8 > 100`
  (the increment happens in the test), it calls `FUN_00501370`, records the score with
  `FUN_00514510(tank, level, profile, Tank+0x3FC)` only if the post-advance level is < 6, and
  opens the BonusScreen `FUN_0054BF60`.

For tanks 1/2/3 the sentinel advances to the next tank L1. Tank 4 L5 never reaches the sentinel:
`FUN_00501370` special-cases tank 4 + level 6 to tank 5 + level 1 (EV-0066), so tank 4 has no
bonus (EV-0076 correction). Tank 5 L1 advances to tank 5/L2 and opens the victory-gate state
(SS7), not a bonus.

### 1.5 Bonus Adventure (`profile+0x59 != 0`, EV-0073)

Every level completion uses the fast path `FUN_0053DC10`:

- `Tank+0x4EE = 1`; `FUN_0053C480([Tank+0x10])`; `FUN_0054B020` (clear overlay slots 0-4 on
  `manager+0x374`, `manager+0x88C/+0x890 = -1`); event `FUN_0054B1A0(2,0x36,0)`; finalizer
  `FUN_00537E20`.
- The same 160-frame wait and bonus starter then run; the bonus duration is
  `base(tank) + clamp(completed level,1,6) - 1` (= 10/15/20/25 + level-1; SS6.1), the advance
  runs, and BonusScreen opens.
- Exception: tank 5 level 1 in Bonus Adventure -> `FUN_00501370` + BonusScreen directly, with no
  Presto grant and no HatchScreen.

This is why the wiki describes a bonus after each tank except 4/5 in Adventure, but after every
stage in Bonus Adventure (EV-0074).

### 1.6 Score records (EV-0067)

`FUN_00514510(tank, level, profile, score)` writes at
`manager+0x8AC + 100 + FUN_00500DD0(tank, level)*12`. For normal completions `score =
Tank+0x3FC` (elapsed seconds). For tank 5 the caller substitutes the number of empty pet slots
`Tank+0x144+i` (excluding index 0x12) plus the combined lengths of the lists at `Tank+0xB0`/
`+0xB4`; the empty-slot indices are also copied to `DAT_005e8fe0` and their count to
`DAT_005e9080` for the credits jokes. Challenge uses `FUN_005144C0(tank, profile, time)`, which
writes `+0x34+(tank-1)*12`.

## 2. Tank init and level-start state `FUN_00541A20` (EV-0061/EV-0072)

- Adventure (mode 0): `Tank+0x3C8` tank = `profile+0x1C`, `Tank+0x3CC` level = `profile+0x20`.
  Other modes: tank = `manager+0x888`, level = 5.

- Final loop: `C[i] = B[i]`, `D[i] = B[i]/100` when `D[i] == -1`; `+0x2DC` = count of items with

- `FUN_0054C540` + ctor `FUN_00542150` create the tank; `profile+0x4C` counts sessions; the ctor
  clears `+0x2A5/+0x4EE`.
- `FUN_0054B2A0` sentinel: true when mode 0 and `profile+0x20 == 6`, or when `Tank+0x2A5 != 0`.

## 6. Bonus rounds

### 6.1 Duration (EV-0068; corrected EV-0076)

`FUN_00537E20` sets `Tank+0x3BC = base + clamp(Tank+0x3CC, 1, 6) - 1`, where `base` by
`Tank+0x3C8`: default/tank1/tank5 = 10, tank2 = 15, tank3 = 20, tank4 = 25. Normal tank
completions run this at level 6 -> tanks 1/2/3 get 15/20/25 s. Bonus Adventure runs it at the
completed level -> 10/15/20/25 + level - 1 s. Tank 4 does not get a normal bonus (its L5 goes
straight to tank 5); tank 5 uses the per-level fast path.

### 6.2 Two-stage wait/start (EV-0068)

- Stage 1: `+0x2A5 != 0`, `+0x2A4 == 0`, `+0x444-+0x2A8 > 0x9F` (160 frames) ->
  `FUN_00537F40` (bonus starter): if `level != 6` emit the tank-complete event; `+0x2A4 = 1`;
  reset `+0x3B4/+0x3B8`; `+0x3B0 = 0`; `+0x2A8 = +0x444`.
- Stage 2: bonus timer expired, `Tank+0xA8` coin list empty, old `+0x3F8 > 100` -> advance,
  optional score record, BonusScreen.

### 6.3 Payout and HUD (EV-0069)

`FUN_0051C8E0` sets the reward and always ends with `FUN_00501200(reward)`:

- mode 0, tank != 5: reward = `Tank+0x3F4`; labels "Level Time"/"Your Best Time".
- mode 0, tank 5: reward = `max(1, profile+0x50-1)*5000`, capped 25000; labels "Surviving
  Pets"/"Your Score"/"Your Best Score". First completion (`+0x50 == 1`) pays 5000; `+0x50`
  increments on every tank-5 level >1 completion, so the exact run-vs-level semantics are open
  -> Q-0015.
- mode 1: reward = `Tank+0x3F0*5/100`, text "%d%% Bonus Award".
- mode 4: tanks 1/2/3/4 -> 2000/5000/10000/20000; "Level Time"/"Your Best Time".
- other modes: no explicit branch (constructor-initialized `this+0xBC` is still paid).
- If no tank exists (`manager+0x730 == 0`), only placeholder "Level Info"/"Bonus Reward" records
  are filled and nothing is paid.

HUD `FUN_0053EAF0`: "BONUS ROUND", "Collect as many shells as you can!", `Tank+0x3F4`, and
"Time Remaining: %d:%02d" from `Tank+0x3BC - Tank+0x3B0` while `+0x2A4`; `+0x3F8` controls the
blinking counter.

### 6.5 Shells persistence `scr%d.dat` (EV-0069; unknown Q-0019)

`FUN_00514B00` reads `FUN_005148C0(1)`, ignores values < 1, clamps >= 100001 to 100000, adds via
`FUN_00501200`, stores the timestamp at `this+0x88`, and saves through `FUN_00514730`.
`FUN_005148C0` formats `userdata/scr%d.dat` with `this+0x44`, deserializes it
(`FUN_0047F5D0`), reads a stored integer, compares it with `this+0x88`, and on a match consumes

timestamp/value meaning remain open.

## 10. Implementation spec for P4 (second pass)

### 10.1 State model

Profile (save):

- `tank` (1-5) and `level` (1-6; 6 is the transient "tank complete" sentinel, 2 on tank 5 is
  the victory gate).
- `owned_pets[24]` bytes + `owned_count`; `selected_pets[24]` bytes; `pet_capacity` base 2
  (`Tank+0x3E4`, demo 8); `challenge_unlocks[5]`.
- `shells` (clamped 0..9,999,999), `sessions_started`, `+0x50` (tank-5 completion counter),
  `bonus_adventure` flag (`+0x59`), `+0x58` (written, reader unknown).
- Challenge records: `+0x34+(tank-1)*12`; score table at `manager+0x8AC+100+index*12`.
- `profile+0xB0` bonus-pet/upgrade card index (1-6); `profile+0xB4` reset 3 / Sandbox 11.

Tank (level instance): `tank_index`/`level` copies (`+0x3C8/+0x3CC`), `money +0x3F0`,
`bonus_shells +0x3F4`, `egg_pieces +0x43C`, `elapsed_seconds +0x3FC`, `bonus_timer +0x3BC`,
`bonus_time_base +0x3B8`, `tank_complete +0x2A5`, `bonus_active +0x2A4`, `+0x2A8` wait anchor,
`+0x2C0` alien countdown, `+0x2BC` alien type, `+0x3E4` pet capacity, `+0x4AC` pellet price,
`+0x4EE` boss/level-end flag, item arrays A/B/C/D and `+0x2DC`.

### 10.2 Level-start algorithm

```
start_level():
    create fresh tank; sessions_started += 1          # every level start (FUN_0054C540)
    init_tank(): tank_index = profile.tank (mode 0) else mode tank
                 level = profile.level (mode 0) else 5
                 money = 999999 if mode==3 else 200
                 egg_pieces = 1 (tank5: 3); pet_capacity = 2 (demo 8)
                 +0x4AC = 5; +0x2C0 = 3000; +0x2BC = 2; +0x2A4/2A8/2C8 = 0
                 build store tables (SS10.3); C=B, D=B/100; visible_count
    if tank_complete or (mode==0 and profile.level==6):
        finalize_tank(); emit_tank_event(); return
    if mode==5: vt_init(); emit_tank_event(); return
    session_init(); emit_tank_event()
```

### 10.3 Store data (JSON-izable)

Encode per tank: `{item, slot, price, hidden_levels[]}` plus `egg_price[5]`, using the SS3 table
and gating. Special cases: tank5 egg price 0 and `egg_pieces = 3`; mode 4 egg overrides
5000/15000/25000 for tanks 2/3/4; mode 1 egg price 100; demo fuller store is out of scope for
Adventure.

### 10.4 Egg completion and reward

```
on_egg_complete():
    elapsed_seconds = (now - level_start) / 1000
    collect_all_coins(); boss_flag = 0
    if mode == 4: challenge_unlocks[tank] = 1; write_challenge_record(); show_bonus(); return
    if bonus_adventure:
        if tank == 5 and level == 1: advance(); show_bonus(); return
        fast_finalize(); return
    advance()
    if tank == 4 and level == 5: show_hatch(999); return          # no grant
    index = 19 if tank == 5 else tank*5 - 6 + level               # completed level
    grant_pet(index); if index == 19: add_shells(5000)
    show_hatch(index)
```

`advance()`: level += 1; if tank == 4 and level == 6 -> tank = 5, level = 1; if tank == 5 and
level > 1 -> `+0x50 += 1`, bonus_adventure = 1; if level > 6 or (bonus_adventure and level > 5)
-> tank += 1, level = 1; `+0x58 = 1`.

### 10.6 Tank-complete / bonus state machine

```
finalize_tank(): clear overlays/globals; tank_complete = 1; bonus_active = 0
                 bonus_timer = base[tank] + clamp(level,1,6) - 1
                 base = [10,10,15,20,25,10] for tank 0..5 (default/tank1..tank5)
                 bonus_shells = bonus_counter = 0; level_start = now
event: level-6 -> (0,0xD); else tank1 (0,0x16), tank2 (0,0), tank3 (2,0x20), tank4 (2,0x2D)
update: if tank_complete and not bonus_active and frames_since(+0x444-+0x2A8) > 160:
            start_bonus()   # bonus_active=1, level_start=now, wait_anchor=now
        if bonus_active and bonus_timer - (now-level_start)/1000 < 0
           and coin_list_empty and bonus_counter > 100:
            advance(); if level < 6: record_score(); show_bonus()
```

### 10.7 Bonus payout / HUD

Implement the SS6.3 switch: mode0 non-tank5 -> `bonus_shells`; mode0 tank5 ->

by tank. Always add via the clamped Shells setter. HUD strings from SS6.3. BonusScreen disables
continue at tank5/L2.

### 10.8 Screens / flow

- PetsScreen: capacity from `Tank+0x3E4` (base 2), 24 pet buttons gated by owned/selected +

- Credits and trophy/story screens: defer until Q-0013/Q-0016 are answered; do not invent a
