- `FUN_004F8AA0` = `Food::Update` (also calls `FUN_004F22C0`, the shared per-tick helper).
  Evidence: `p2.3-food-4F8AA0.json`.
  1. Gates: returns unless `[manager at [0x22]+0x730]` (tank) exists and `tank+0x94` (pause) == 0.
  2. `FUN_004F22C0()`; decrement `[0x66]`; cycle `[0x5E]` wraps at `[0x5F]*10 - 1`;
     if `[0x62] == 3` (star potion) set byte `+0x55 = 1`.
  3. If lifetime `[0x60]` != 0: decrement; when it hits 0 -> `FUN_004D9570()` (remove) + return.
  4. Movement: if `(+0x190 == 0 || +0x184 != 0)`:
     - `+0x185 == 0` -> fall: `y += 1.5` per tick.
     - else -> **homing**: `x += (550.0 - x) / 7`, `y += (30.0 - y) / 7`; if `int x < 40`
       -> `FUN_004D9570()` (remove) + `FUN_0053C1E0()`; then tail slot 41 (0xA4) with RNG.
       Target (550, 30) is a constant [open: which mechanism uses it; candidate: being
       vacuumed/collected - see also `DAT_005e89d0/4/8` in §9 of P2.2 note].
  5. else (landed and not flagged): staged "bob up" by depth: `y >= 150` -> `y -= 8`;
     `135..150` -> `-2.5`; `130..135` -> `-1.5`; `125..130` -> `-1.0`; `120..125` -> `-0.5`;
     `y < 120` -> set `+0x184 = 1` (=> next tick falls again) - i.e. pellets bob between
     ~120 and ~150.
  6. `[0x18C]` != 0 (drift kind): vy < 0 -> `vy += 0.05` (and `y += vy`); kind 2: `vx > 0` ->
     `vx -= 0.05`; kind 1: `vx < 0` -> `vx += 0.05` (and `x += vx`) - drift decays to 0.
  7. x clamp: `x > 550` -> `x = 550.0`; `x < 20` -> `x = 20.0`.
  8. Death: `y > 410` (or `y > 400` when `[0x62] == 3`):
     - `[0x62] == 3`: sound 0x11D + 2..4 particles via `FUN_005436F0` around `(x +/- 10, y + 3..5)`
       + remove.
     - `[0x65] == 2` (variant 2): remove (no splash).
     - else: `y = FUN_004D62D0()` (float result - **identity open**: bounce/float-back?).
  9. Tail: `[Tank+0x10]` object vtable slot 0xA4 call with an RNG arg (same tail as Fish).

## 2. Drop flow: `Tank::DropFood` `FUN_00543280` (fully decoded)

Signature (Ghidra): `FUN_00543280(x, y, kind, flag, param_5, param_6)`.
- `kind == 0` = manual drop (click): pellet-cap check against the food list container at
  `Tank+0xAC`:
  - count `specials` = food objects with `[0x18C] != 0 || [0x194] != 0`;
  - **refuse when `DAT_005df58c + specials <= total_count`** => at most `DAT_005df58c`

    unlimited.
  - On refusal, hint text depends on `FUN_00537BB0()` + tutorial counters
    (`Tank+0x118 + 0xD0`, player flag `Tank+0x3A7`):
    `"You can only drop 1 food pellet at a time for now"` or

- Creates `new(0x1A0)` + `FUN_004EF840(x, y, kind, flag, param_5)`.
- `Food+0x188 = DAT_005e89dc` (**food quality level**, 0..2, see P2.5 note);
  `kind != 0` -> `+0x188 = 1`.
- **Star potion drop**: if `Tank+0x440 != 0` and `kind == 0` and `flag == 0` ->
  `Food+0x188 = 3` + clear `Tank+0x440` (potion pellet - see §7 for effect).
  When `Tank+0x440 == 0` and `kind == 0` (or flag set) -> `FUN_00538230()` (role open).
- `param_6 != -1` -> override `Food+0x188 = param_6`; `param_5 >= 0` -> `Food+0x198 = param_5`.
- `FUN_00542EE0(food, ...)`, add via `[Tank+0x10]` vtable slot 3, `FUN_0053AA40()` (UI).

Callers: fish click virtual (slot 54, see §3) plus Tank-side cluster `0x543441`, `0x54352E`,

## 5. Fish hunger model (second pass; evidence `p2.3-eat-*`, `p2.3-fishslot82.json`)

- **Hunger counter = int at `Fish+0x9C` (`[0x27]`)**, signed. Starts ~0, can go highly positive
  after eating, decreases 1 per tick:
  - `FUN_004D6EF0` (called from slot 82 when `Tank+0xB8`/`+0xF4` lists are empty): if
    `[0x11C] == -1` (no active effect handle) -> `[0x9C] -= 1`; clamp at `-1000`;
    when `[0x9C] == [0xA4] + 4` -> `FUN_004D6920(1)` (transition, role open).
- **Threshold behavior (slot 82 = `FUN_004F15C0`, byte-gated by `+0x228`)**:
  | `[0x9C]` | action |
  | --- | --- |
  | `-1` | hint `"Fish are hungry! Click to drop food!"` (tank tutorial flags `+0x4C7`/`+0x4B8`) |
  | `-200` | `"Fish are REALLY hungry! Click to feed!"` + `FUN_00538230()` |
  | `-400` | `"Fish are about to die of hunger! Click on aquarium!"` |
  | `< -499` | **death: call slot 88** (shared die `0x4D5F90`) |
  | `< 500` (i.e. -499..499) | call slot 84 (approach/eat, §7); if tank `+0xB8` empty -> slot 84 anyway |
- Pets (`obj+0xAC < 0`): `FUN_004D69D0` = pet starvation check - demo thresholds `-2159`
  (normal) / `-4319` (type ids 7/8/9); non-demo: `[0x9C] < 1`.
- Hit-flash counter `[0xA0]` decays via `FUN_004D6C50` (blink 5..0).
- `FUN_004D6F30` = sprite-state predicate (zombie mode uses it for column 9 normal / 6
  hungry-alt): true when `[0x9C] < 301 && [0xA0] == 0 && ([0x148] < 3 || Tank+0x4FF)`.
- Tint/frame selection: `FUN_004D5AA0(normal?)` returns a color index from the runtime

## 6. Food-seeking (Fish::Update `FUN_004F6970`, evidence `fish-update-pseudo.txt`)

  follow** toward `(DAT_005e89d4, DAT_005e89d8)` (the food/target point; serialized globals),
  accel steps +/-5/3/1 by distance bands; the three globals are tank-serialized (EV-0044).
- Else `slot 82` decides; if it did nothing: when `Tank+0xB8`/`+0xF4` empty or
  `Tank+0x174 == 0` or `!fish+0x229` -> normal wander (direction machine `[0x1AC]` 0..4 + 0x7B
  special, timers `[0x1B0]`/`[0x1B4]`, speed reduction `[0xF6]`), otherwise **food seek**:
  iterate entities with `field+0x234 == 0xC` (food class marker) and steer with distance

  the y drift gain becomes 1.0/0.75/0.5/0.25 (engine quirk); if `[0x190] < 0x141` ->
  `y -= 0.25`; sparkle trail during `[0x208]`
  dart timer (50%, 2 particles; type 6 = 7 particles); slot 89 each tick; then

## 7. Eating pipeline (Guppy impls; per-species slots)

Species vtable slots (Guppy values; others per-class): 81 = coin scheduler, 84 = approach,
85 = target find, 86 = eat, 77 = consume. Guppy: slot84 `0x4D5B20`, slot85 `0x4EF050`,
slot86 `0x4EF1B0`, slot77 `0x4F1BA0`.

1. **Approach (slot 84)**: requires timer `[0x1B0] > 2`; gets target from slot 85; resets
   `[0x1B0]`; steers toward target center with two accel profiles:
   `[0x9C] < 301` (normal: vx +/-1.3/0.2/0.05 clamp 4, vy -1.0/-0.5/+0.7) vs `[0x9C] >= 301`
   (sluggish: vx +/-1.0/0.1/0.05 clamp 3, vy -0.6/-0.3/+0.5); bumps anim counter `[0x1BC]`
   (max 5); when target exists -> slot 86.
2. **Target find (slot 85)**: if `[0xF0] != 0` -> bubble-food path `FUN_004EA010(center x,
   center y + 20)`; else nearest food by distance (`FUN_004D5F20` acceptance + distance) -
   if nearest < 100 px -> `FUN_004D6B00(150)` + `[0xF8] = 100` (excited timer).
3. **Eat detect (slot 86)**: while `[0x3C] == 0`, iterate `Tank+0xAC`:
   - near window (`x +/- ~35`, `y +/- ~35` referenced to +40 center offsets) + acceptance ->
     **slot 77 consume(food)** + `FUN_004D9570()` remove + `[0x1C8] += 8` (eat fx) +
     `FUN_004D6CC0()` (sound).
   - wider window -> `[0x1C8] = 0x14` (mouth-open anticipation, no consume).
   - `[0x3C] != 0` path: `FUN_004EA2A0(center, y+20)` -> result 1/2 sets `[0x1C8] = 8 / 0x14`.
4. **Food acceptance `FUN_004D5F20(food)`** (shared): reject if `food+0x185 != 0` or
   `food+0x198 != 0`; `variant != 2` -> accept iff `variant == 0`; `variant == 2` -> accept
   iff mode 5, or (`fish stage < 3` and `[0x9C] < 108`).
5. **Consume (slot 77, Guppy `0x4F1BA0`)** - the nutrition/growth model:
   - `variant == 2` (breeding pellet): mode 5 -> cap `[0x9C]` at 30 + effect; else when
     stage < 3: call slot 87 (`0x15C`, produce) + `FUN_00544A90()` (if returns obj set
     `+0x240 = 1`) + `FUN_005392A0()` gate + **spawn guppy `FUN_00546D70()`** and return
     => breeding pellet turns into a new guppy.
   - else by quality `Food+0x188`:
     | quality | effect |
     | --- | --- |
     | 0 | `[0x9C] += 500` (+200 if `+0x228`), cap 800; `[0x69] += 1` |
     | 1 | `[0x9C] += 700`, cap 1000; `[0x69] += (mode!=5 ? 2 : 1)` |
     | 3 (star potion) | stage <= 1: particles (`FUN_005436F0` x2..4 via RNG) + tutorial hints + `Tank+0x49C++` + **die (slot 88)**; stage == 2: `[0x9C] += 1100` cap 1400 + **stage = 3** + `FUN_00538230()`; stage >= 3: `[0x9C] += 1100` cap 1400 |
     | other (2) | `[0x9C] += 500` cap 800 (mode 5) or `+1100` cap 1400; `[0x69] += (mode!=5 ? 2 : 1) + 1` |
   - `[0x69]` = int `+0x1A4` (food points), `[0x6A]` = int `+0x1A8` (points needed per stage).
   - **Growth**: when `[0x69] >= [0x6A]`: if stage `[0x1A0] < 2` -> stage++, `FUN_004F1840()`
     (grow sfx/anims), `[0x69] = 0`, `[0x1CC] = 10` (grow-pop animation timer used by draw),
     `FUN_00538230()`; if overshoot `(mode5 ? 8 : 15) * [0x6A] <= [0x69]` and stage > 1 and
     stage != 4 and `+0x1D0 == 0` -> **stage = 4** (final fat stage) + `FUN_00538230()`.
   - Mode-5 economy→hunger coupling: cap `[0x9C] <= 30` etc. (virtual tank parity).
6. **Death**: slot 88 shared `0x4D5F90` (hunger < -499, star potion on small guppy, plus
   other callers). DeadFish class handles the corpse animation (P2.4).

## 10. Implementation spec for P4 (feeding)

- `Food` (Node2D): fields as §1 with **two speed profiles** (drop: fall 1.5; landed bob cycle
  120..150 staged; drift decay 0.05). Death at y 410 (star 400) with star splashes for
  quality 3. Lifetime `[0x60]` is 0 for normal pellets (no auto-expiry for dropped food;
  expiry only for specific types) - implement exactly as §1.3.
- Feeding: click in water (bounds 30..587 x 60..400 - account for UI strip at bottom) spends
  `Tank+0x4AC` and drops a pellet at the cursor (round coords); latch `+0x4EC`/`+0x4ED`
  for hold-to-feed; pellet cap: at most `food_quantity_level` non-special pellets in the
  tank (specials exempt); refusal hints per §2 (tutorial flags).
- Hunger per fish: `fullness` int (starts 0) decremented 1/tick while no active effect;
  exit thresholds -1/-200/-400 (hint + HUD) and -500 (death); clamp -1000; eating adds
  +500 (quality 0) / +700 (quality 1) / +1100 (quality >= 2 & star) with caps 800/1000/1400.
- Eating: per-species approach/eat/consume virtuals; Guppy behavior per §7 (approach accel
  bands, eat window ~35 px, mouth-open at ~50 px windows, consume applies nutrition, growth
  points `[0x69]`/`[0x6A]`, stage transitions 0->1->2->(3 via star)->4 via huge overshoot).
- Star potion: `Tank+0x440` armed flag -> next manual drop is quality 3; small guppies die,
  stage-2 guppy -> stage 3.
- Coin drops: per-fish counter `[0x220]` reaching a per-species/stage threshold -> SpawnCoin
  (kind/value table in P2.5 note §5, virtual-tank multipliers there); demo mode blocks coins
  from starving fish.
