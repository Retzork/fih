## 1. Food entity

- Class `Sexy::Food`, type id **0x1C (28)**, alloc size 0x1A0, vtable 0x59817C.
  - Bare ctor `FUN_004EF820` (factory / save-load path) - vtable + `[0x23] = 0x1C`.
  - **Play ctor `FUN_004EF840(x, y, kind, flag, variant)`** (also 2 extra caller args ->
    `param_5`/`param_6` handling below; 6-arg signature in Ghidra). Evidence
    `p2.3-foodctorxy.json`.
- Food field map (byte offsets; int* indices in `FUN_004F8AA0` are *4):

| offset | ctor value | role (from ctor + Update) |
| --- | --- | --- |
| `+0x158` (dbl) | `x` | x position |
| `+0x160` (dbl) | `y` | y position |
| `+0x168` (dbl) | kind==2 ? +2.0 : -2.0 | vx (drift, sign by kind) |
| `+0x170` (dbl) | -2.0 | vy (starts rising) |
| `+0x30`/`+0x34` | rand, rand | 2 random ints (used for death particles; exact meaning open) |
| `+0x38`/`+0x3C` | 0x28 | sprite size 40x40 |
| `+0x184` byte | 0 | Update gate flag (`[0x61]`) |
| `+0x185` byte | 0 | "sucked/homing" flag (see section 3) |
| `+0x188` int | 0, then set by dropper | **food quality/type**: dropper writes `DAT_005e89dc` (quality level) or 1 / 3 (star potion) or override |
| `+0x18C` int | kind (param 3) | drift kind (also used by death logic, `[99]`) |

| `+0x17C` int | `(rand & 1) + 3` | anim cycle length ([0x5F]; 3 or 4) |

| `+0x198` int | 0x14 (20) | countdown ([0x66]; `Tank::DropFood` sets it when `param_5 >= 0`) |

- `FUN_004F8AA0` = `Food::Update` (also calls `FUN_004F22C0`, the shared per-tick helper).
  Evidence: `p2.3-food-4F8AA0.json`.
  1. Gates: returns unless `[manager at [0x22]+0x730]` (tank) exists and `tank+0x94` (pause) == 0.
  2. `FUN_004F22C0()`; decrement `[0x66]`; cycle `[0x5E]` wraps at `[0x5F]*10 - 1`;
     if `[0x62] == 3` (star potion) set byte `+0x55 = 1`.
  3. If lifetime `[0x60]` != 0: decrement; when it hits 0 -> `FUN_004D9570()` (remove) + return.
  4. Movement: if `(+0x190 == 0 || +0x184 != 0)`:
     - `+0x185 == 0` -> fall: `y += 1.5` per tick.
     - else -> **homing**: `x += (550.0 - x) / 7`, `y += (30.0 - y) / 7`; if `int x < 40`
       -> `FUN_004D9570()` (remove) + `FUN_0053C1E0()`; then tail slot 41 (0xA4) with RNG.
       Target (550, 30) is a constant [open: which mechanism uses it; candidate: being
       vacuumed/collected - see also `DAT_005e89d0/4/8` in §9 of P2.2 note].
  5. else (landed and not flagged): staged "bob up" by depth: `y >= 150` -> `y -= 8`;
     `135..150` -> `-2.5`; `130..135` -> `-1.5`; `125..130` -> `-1.0`; `120..125` -> `-0.5`;
     `y < 120` -> set `+0x184 = 1` (=> next tick falls again) - i.e. pellets bob between
     ~120 and ~150.
  6. `[0x18C]` != 0 (drift kind): vy < 0 -> `vy += 0.05` (and `y += vy`); kind 2: `vx > 0` ->
     `vx -= 0.05`; kind 1: `vx < 0` -> `vx += 0.05` (and `x += vx`) - drift decays to 0.
  7. x clamp: `x > 550` -> `x = 550.0`; `x < 20` -> `x = 20.0`.
  8. Death: `y > 410` (or `y > 400` when `[0x62] == 3`):
     - `[0x62] == 3`: `FUN_00538230(0x11D, 3, 1.0)` (sound) + spawn 2..4 particles via
       `FUN_005436F0` around `(x +/- 10, y + 3..5)` + remove.
     - `[0x65] == 2` (variant 2): remove (no splash).
     - else: `y = FUN_004D62D0()` (float result - **identity open**: bounce/float-back?).
  9. Tail: `[Tank+0x10]` object vtable slot 0xA4 call with an RNG arg (same tail as Fish).

## 2. Drop flow: `Tank::DropFood` `FUN_00543280`

Signature (Ghidra): `FUN_00543280(param_1, param_2, param_3, param_4, param_5, param_6)`.
- `param_3 == 0` = manual drop (click): pre-check against the food list container at
  `Tank+0xAC`; pellet cap depends on `DAT_005df58c` (food quantity level) plus a count of
  "non-plain" pellets (`[0x18C] != 0 || [0x194] != 0`). Exact formula ambiguous
  (`level + specials <= total` gate) - mark open, verify empirically later.
  On refusal: hint `"You can only drop 1 food pellet at a time for now"` (or
  `"Upgrade Food Quantity to drop more food at once!"`, hint player flags `+0x3A7` etc.).
- Creates `new(0x1A0)` + `FUN_004EF840(...)`.
- `Food+0x188 = DAT_005e89dc` (**food quality level**, 0..2, see P2.5 note);
  `param_3 != 0` -> `+0x188 = 1`.
- **Star potion drop**: if `Tank+0x440 != 0` and `param_3 == 0` and `param_4 == 0` ->
  `Food+0x188 = 3` + clear `Tank+0x440` (star potion pellet - death splash path above).
- `param_6 != -1` -> override `Food+0x188 = param_6`; `param_5 >= 0` -> `Food+0x198 = param_5`.
- `FUN_00542EE0(food, ...)`, add via `[Tank+0x10]` vtable slot 3, `FUN_0053AA40()` (UI).

Callers (all in Tank input cluster): `0x543441`, `0x54352E`, `0x5435F2` - which is click vs
auto-feed (hold) vs scripted is open. Evidence: `p2.3-dropfood.json`, `p2.3-foodxy-xrefs.json`.

## 5. Implementation spec for P4 (preliminary)

- `Food` (Node2D): fields as §1; state machine: FALL (y += 1.5*dt) -> LANDED/BOB (staged rise
  cycle 120..150) -> REMOVE (lifetime or y > 410 with splashes for type 3). Drift vx/vy decay
  for drifting pellets (kinds 1/2).
- Drop API mirroring `Tank::DropFood`: `drop_food(x, y, kind, flag, variant, type_override)`;
  quality/quantity as tank-level ints (0..2 / 0..9); star-potion armed flag flips type to 3.
- Constants: sizes 40px, clamps x [20, 550], death y 410/400, fall speed 1.5, homing divisor 7.
