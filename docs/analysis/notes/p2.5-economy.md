## 1. Money

- **Player money = `Tank+0x3F0`** (int; serialized by `FUN_00546240`, see P2.2 note §9).
- `FUN_00540B30(amount, playSound)` = `Tank::SpendMoney(amount)` -> bool:
  - Mode `[manager+0x87C] == 5` => always succeeds (no economy in that mode) and no-op.
  - "Demo" floor: when `[manager+0x880] != 0` and `money < 5` -> `money = 5` (before and
    after spending) - keeps a minimum of 5.
  - Affordability: `spendable = money + FUN_0053A0B0()` where `FUN_0053A0B0` is **not a loan**
    (EV-0057): it sums the value of uncollected coins lying in the tank - lists `+0xA8` and
    `+0xEC` via `Coin::Value()` `FUN_004D53A0` for members with byte `+0x198 != 0`, plus list
    `+0xC8` (offset 200) via `FUN_004D7E60()` for members with byte `+0x174 != 0`. The
    `"OUT OF MONEY! ... we'll float you a loan"` @0x5A8300 flavor text is explained by this:
    coins already on the tank floor count toward a purchase before you click them.
  - If `money + loan < amount`: play sound `0x112` (rate-limited by `Tank+0x450` cooldown
    ​= 70 ticks), hint when `money == 0` via `FUN_00537B80()` (hint screens) +
    `FUN_0054B5B0(0x13, 1, ..., 3)` (3-part message dialog) -> return 0.
  - Else `money -= amount` (floor 5 re-applied), `FUN_0053A360()` (money UI refresh) -> 1.
- `FUN_0053C2D0()` = **collect all pending coins**: `money += FUN_0053A0B0()`, clamp
  0..9,999,999, `FUN_0053A360()` refresh. Callers: egg/level handler at `0x545BFD`,
  `Tank::Update` at `0x547A17` and `0x548F3D` (mode flow timeouts) - i.e. all coins in the
  tank are banked when a level/flow ends.
- `DAT_005df590` = separate "demo money" global: seeded in LoadGame when
  `thunk_FUN_00479FC0()` (demo/registered check) to `rand` clamped 5000..50000; compared in
  `FUN_004D70B0` (fish method): in mode 5 with `tank+0x500 != 0`: allowed iff `tank+0x400 <=
  DAT_005df590`; otherwise returns 1. Open: exact role (demo trial gating).
- `"ShowMoney"` INI option -> `TankScreen+0x83C` (options block `+0x839`..`+0x83E`:
  Sound/RotateBackDrops/PeriodicDim/ShowMoney/Powersave; loader `FUN_0054E2D0`, section name
  at `TankScreen+0x788`).

## 3. Purchase hub `FUN_00549380` = `Tank::BuyItem()`

- Selected item + price from `FUN_00538090(index)` (0 = item not present). Store getters
  (EV-0057): `FUN_00538090(i)` = item UI object - `slot = A[i] (+0x2E4)`; `slot < 0` -> 0,
  else `Tank+0x404 + slot*4`. **The four parallel 12-int arrays (all serialized by
  `FUN_00546240`, EV-0045) are (EV-0057):**
  - `+0x2E4[12]` (**A**) = store slot id per item (-1 = item not for sale/disabled),
  - `+0x314[12]` (**B**) = current price (what the player pays; egg piece price is B[11],
    aliased at `+0x340`),
  - `+0x344[12]` (**C**) = base price (the reset target),
  - `+0x374[12]` (**D**) = per-tick price increment (mode-4 inflation).
- `FUN_005380C0(index, price)` = `Tank::SetStorePrice`: clamp to 99999, `B[index] = price`,
  then refresh the item row via `FUN_00534380(slot)` if the item object exists. Only three
  call sites exist (xrefs 0x545A9A, 0x545B81, 0x54810E):
  - 0x54810E (in `Tank::Update`, mode 3 && `Tank+0x2E0 < Tank+0x2DC` && tank `+0x3C8 != 5`):
    create all 12 store items (`FUN_005409B0(i, 1)`) then `SetStorePrice(11, 0)` - egg piece
    starts at 0 when the store (re)builds;
  - 0x545A9A (egg handler, mode 1 "random pet" branch): `SetStorePrice(11, 2 * B[11])` - the
    price of the **next random pet doubles** each purchase; `+0x498 += 1` counts these;
  - 0x545B81 (egg handler, mode 4 branch): `SetStorePrice(i, C[i])` for all i != 11
    ("Prices have been reset!").
- Initial values of A/C/D for a fresh tank are NOT written by any store code path; they are
  level/tank data entering via serialize/load (`FUN_00546240` reads all four arrays) or the
  `Tank::Update` mode-3 rebuild (`+0x2DC` = target item count, `+0x2E0` = items created).
  Bounded search: decompiled `FUN_00538090`, `FUN_005409B0`, `FUN_005406A0`, `FUN_00546240`,
  `FUN_00537D30`, `FUN_00546AA0`, plus all 3 setter xref sites - no static price tables.
  Hand-off to P2.6 (progression/level data).
- Every case: `FUN_00540B30(price[, 1])` first (spend) -> abort on fail.
- Guppy case also: hint `"You can't afford new fish yet! Collect more money!"` when
  `FUN_00537BB0()` and `money < price`; clears tutorial byte `Tank+0x4B2`.
- Food upgrade cases: tutorial hints (`"Upgrade Food Quantity to drop more food at once!"`,
  `"Hold down mouse button to Auto-Feed!"`) gated on `Tank+0x3C8`/`+0x3CC` (tutorial step
  counters) and player flags.
- Star potion case: `"Click on tank to drop star potion!"` + sets `[Tank+0x118]+0xD0 = 180`
  (cursor icon timer?).
- Case 11: `FUN_00545960` (no spend inside this switch case visible - handles egg logic).
- Post-purchase common: `FUN_005406A0()` (apply upgrade -> rebuild?), `FUN_00538230()`
  (sound), `FUN_00538360()`, `FUN_005409B0()` (tutorial advance).

### 3.1 Egg piece / "buy random pet" / "end level" handler `FUN_00545960` (EV-0057)

Store item 11 (label per mode: "buy random pet" mode 1, "end level" mode 3, else egg piece).
Verified flow (decompiled + assembly + basic blocks of `0x545960`):

1. `FUN_00538090(0xB)`; item object missing -> return.
2. `mode == 3`: `FUN_00552230()`, return (**no spend**).
3. Spend price `B[11]` (`+0x340`) via `FUN_00540B30(price, 1)`; fail -> return.
4. `mode == 1` ("buy random pet"): build a candidate vector from the tank's **24 pet slots**
   (`Tank+0x144 + i*4`, i < 0x18, skip occupied and i == 0x13, filter `FUN_00501410(profile, i)`);
   if non-empty pick `vector[rand() % size]` and grant via `FUN_00544A90(petId, -1, -1, 0, 0)
   (Tank+0x498 += 1; SetStorePrice(0xB, 2*B[11])` - **the next random pet costs double**); if
   candidate count <= 1 -> `FUN_00534450(item11Obj)`; sound `FUN_00538230(0x111, 3, 1.0)`; free
   vector; **return** (no egg accounting in this branch). `Tank+0x498` = random-pet purchase
   counter in this branch (also serialized).
   -> `Tank+0x144[24]` = per-tank pet slots (ownership/unlock array; cross-ref P2.7/P2.13).
5. Otherwise (egg path): clear pending byte `+0x4D8` (sets `+0x4E6 = 1`, `+0x4E8 = 0`);
   tutorial hint "Collect 2 more egg pieces to finish level!" when tutorial active
   (`FUN_00537BB0`) and `Tank+0x43C == 1` on entry; `Tank+0x43C += 1`;
   `mode == 4`: `Tank+0x454 = 500` + `SetStorePrice(i, C[i])` for all i != 11
   ("Prices have been reset!" when `+0x43C <= 3`); `FUN_005406A0(0xB, 1)`; sound `0x111`.
6. `Tank+0x43C < 4` -> return (up to 4 egg pieces per egg/level-cycle).
7. `Tank+0x43C >= 4` (egg complete): `Tank+0x3FC = FUN_00538040()`; `Tank+0x4EE = 0`;
   `FUN_0053C2D0()` (bank all pending coins); then:
   - `mode == 4`: unlock byte `[profile+0x8B8 + 0x77 + tankIdx] = 1` for tanks 1..4 (tank index
     `Tank+0x3C8`), `FUN_005144C0()`, `FUN_0054BF60()` (level-complete flow), return;
   - else: `FUN_00514510()` then flow by profile byte `+0x59`; `Tank+0x3C8 == 5` special case
     rebuilds a free-pet list into globals `DAT_005e8fe0`/`DAT_005e9080`; statistics slot
     `tankIdx*5 - 6 + levelIdx` (tank `+0x3C8`, level `+0x3CC`) via `FUN_00501420`; jingles
     `FUN_00501370` (slot 0x13 -> `FUN_00501200`) and screens `FUN_0054BF60`/`FUN_0054BE80`/
     `FUN_0053DC10`.
   -> `Tank+0x43C` = egg pieces owned (0..4), `Tank+0x498` = counter, `Tank+0x3C8` = tank index
   (1..5), `Tank+0x3CC` = level index; `Tank+0x144[24]` pet slots; mode-4 is the mode with
   price inflation + tank-complete unlock (P2.6/P2.11 to name it).

## 8. Implementation spec for P4 (preliminary)

- Money as `Tank.money` int with the same spend gate order (mode-exempt -> demo floor 5 ->
  affordability = money + value of uncollected coins in the tank -> sound/hint -> subtract);
  "collect all" (`FUN_0053C2D0`) banks those coins at level/flow end.
- Store as data table: 12 items {id, name key, price, handler}; handlers mirror §2.
- All purchases funnel through one `buy_item(index)` with the spend precheck; upgrades are
  tank-level counters (food quality 0..2, food quantity 0..9, weapon 0..11).
- Coins: falling entities with a kind->value table (§5), bob/land at the tank floor (y=370),
  expiry thresholds, and collection by proximity to non-Fish creatures/collectors; reproduce
  the per-list dispatch order from EV-0055 once the gameplay-intent check (Q-0010) is done.
